# Build non-whitelist GeoIP detection

## Preconditions and setup actions
- RADAR is set up according to [TST-041](./TST.html#TST-041): `radar/.env` filled in, Docker available on the controller host.
- A Linux endpoint reachable from the manager, with `sudo`.

## Test steps

1. On the controller host, the working directory is required to be `radar`:
```
cd radar
```

2. Build RADAR with the `geoip_detection` scenario (prefix with `sudo` if your user cannot run Docker):
```
./build-radar.sh geoip_detection
```
This brings up the core stack (indexer, manager, dashboard) and the webhook container, then deploys the scenario's manager-side files, agent group configuration, decoders, rules and lists.

3. Onboard the endpoint (see docs/manual/radar_docs/radar-getting-started.md, *Onboard an endpoint*):
```
sudo ./radar.sh mint-token default,geoip_detection,radar_shared 60
```
Copy the whole `radar/radar-agent/` folder to the endpoint and, from inside it, run the printed command, e.g.:
```
sudo ./bootstrap-agent.sh --manager <address> --token <token> --group default,geoip_detection,radar_shared
```

4. To clean up the test environment **only after** a _successful_ test execution **AND** a successful execution of [TST-047](./TST.html#TST-047):

- On the controller host: `./stop-radar.sh` (add `--purge` to also remove the volumes).
- On the endpoint, from the `radar-agent` folder: `sudo ./uninstall-agent.sh`.
## Expected outcome

### 2. Check the setup

#### In Wazuh Manager

Connect to the Wazuh manager to be able to perform the following verifications:
```
docker exec -it wazuh.manager bash
```
- **2.1** The whitelist is deployed and declared:
```
cat /var/ossec/etc/lists/whitelist_countries
grep -n 'whitelist_countries' /var/ossec/etc/ossec.conf
```
to ensure the list holds the scenario's entries (`LU:`, `DE:`, `FR:`, `BE:` as shipped) and `ossec.conf` has a `<list>etc/lists/whitelist_countries</list>` entry under `<ruleset>`.

- **2.2** The RADAR-aware SSH and web access log decoders are deployed:
```
ls -l /var/ossec/etc/decoders/0310-ssh.xml /var/ossec/etc/decoders/0375-web-accesslog.xml
```
to ensure both files exist.

- **2.3** The stock decoder files they replace are excluded in `ossec.conf`:
```
grep 'decoder_exclude' /var/ossec/etc/ossec.conf
```
to ensure `0310-ssh_decoders.xml` and `0375-web-accesslog_decoders.xml` are each excluded once under `<ruleset>`.

- **2.4** The GeoIP rules are deployed:
```
grep -o 'rule id="[0-9]*"' /var/ossec/etc/rules/a2-geoip-detection.xml
```
to ensure rules 100900, 100901, 100902 and 100903 are present.

- **2.5** The rules are bound to the RADAR active response:
```
grep -A20 'RADAR: geoip_detection BEGIN' /var/ossec/etc/ossec.conf
```
to ensure the `radar_ar_geoip` command runs `radar_ar.py` with `<location>server</location>` for `<rules_id>100900,100901,100903</rules_id>`.

- **2.6** Both enrichment integrations are installed and wired:
```
ls -l /var/ossec/integrations/custom-radar-enrich /var/ossec/integrations/custom-radar-web-enrich /var/ossec/integrations/radar_enrichment/
grep -B1 -A3 'custom-radar' /var/ossec/etc/ossec.conf
ls -l /var/ossec/etc/radar/
```
to ensure both scripts and their modules exist, `custom-radar-web-enrich` is declared for the `accesslog` group and `custom-radar-enrich` for `authentication_success,authentication_failed`, their enriched log files are read back as `localfile`, and the GeoLite2 databases are present.

- **2.7** The agent group configurations are in place:
```
cat /var/ossec/etc/shared/geoip_detection/agent.conf /var/ossec/etc/shared/radar_shared/agent.conf
```
to ensure they collect the Apache access logs and `/var/log/auth.log`.

- **2.8** Active response files are in place:
```
ls -l /var/ossec/active-response/bin/radar_ar.py /var/ossec/active-response/bin/ar.yaml /var/ossec/active-response/bin/active_responses.env
```
to ensure all three exist.

- **2.9** The agent is registered with the manager:
```
/var/ossec/bin/agent_control -l
```
to ensure an active entry exists for the endpoint (and one for the webhook agent, `ad-webhook`).

- **2.10** Wazuh Manager is running after the deployment:
```
/var/ossec/bin/wazuh-control status
```
to ensure the status output indicates the manager is `running` with no error messages.

#### In endpoints running agents

- **2.11** The Wazuh agent is active and the RADAR active response scripts are installed:
```
systemctl status wazuh-agent
ls -l /var/ossec/active-response/bin/lock_user_linux.sh /var/ossec/active-response/bin/terminate_service.sh
```
to ensure the agent service is active and both scripts exist.
