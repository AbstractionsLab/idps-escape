# RADAR credential rotation

No automated test covers credential generation or rotation; this test is run by hand on a stack RADAR deploys itself.

## Preconditions and setup actions

- A RADAR host with Docker and `sudo`, and no earlier RADAR stack: `docker volume ls | grep wazuh-indexer-data` prints nothing.
- `radar/.env` created from `radar/env.example`, with `OS_PASS`, `WAZUH_AUTH_PASS` and `INDEXER_DASHBOARD_PASSWORD` empty or set to the stock Wazuh values.
- All commands run in `radar/`. To use a value from `.env` in a command without printing it, read it with `v() { python3 -m wazuh_api.envfile get "$1" .env; }` (the RADAR scripts need the same Python modules). Define `os_ok() { curl -sk -o /dev/null -w '%{http_code}\n' -u "admin:$1" https://localhost:9200/_cluster/health; }` and `api_ok() { curl -sk -o /dev/null -w '%{http_code}\n' -u "wazuh-wui:$1" -X POST https://localhost:55000/security/user/authenticate; }`.

## Test steps

1. **First deployment**: `sudo ./build-radar.sh --core-only`. Then `stat -c '%a' .env`, `stat -c '%a' .radar-generated`, `ls -a .radar-generated`, and check that `.radar-generated/internal_users.yml` contains no value of `.env`.
2. **Generated passwords in use**: `os_ok "$(v OS_PASS)"`, `os_ok SecretPassword`, `api_ok "$(v WAZUH_AUTH_PASS)"`, `api_ok 'MyS3cr37P450r.*-'`, `curl -sk -o /dev/null -w '%{http_code}\n' -u readall:readall https://localhost:9200/_cluster/health`. Log in to the dashboard as `admin` with `OS_PASS`.
3. **Existing deployment kept**: `sha256sum .env > env.sum`; `sudo ./stop-radar.sh`; `sudo ./build-radar.sh --core-only`; `sha256sum -c env.sum`.
4. **Deploy a scenario** so that the manager has an `active_responses.env`: `sudo ./build-radar.sh log_volume`.
5. **Refusals**: `sha256sum .env > env.sum`; `./radar.sh rotate-credentials` (without `sudo`); then `docker stop wazuh.indexer`, `sudo ./radar.sh rotate-credentials`, `sha256sum -c env.sum`, `docker start wazuh.indexer` and wait until `os_ok "$(v OS_PASS)"` returns 200.
6. **Rotation**: `OLD_OS="$(v OS_PASS)"; OLD_API="$(v WAZUH_AUTH_PASS)"`; `sudo ./radar.sh rotate-credentials; echo $?`.
7. **New passwords in use, old ones refused**: `os_ok "$(v OS_PASS)"`, `os_ok "$OLD_OS"`, `api_ok "$(v WAZUH_AUTH_PASS)"`, `api_ok "$OLD_API"`; compare `sudo sha256sum .radar-state/env.before-rotation` with `env.sum`; `sudo stat -c '%a' .radar-state/env.before-rotation`. Log in to the dashboard as `admin` with the new `OS_PASS`.
8. **Active response environment**: `docker exec wazuh.manager stat -c '%U:%G %a' /var/ossec/active-response/bin/active_responses.env`; `docker exec wazuh.manager grep -qxF "OS_PASS=$(v OS_PASS)" /var/ossec/active-response/bin/active_responses.env; echo $?`.
9. **Deployment still healthy**: `./health-radar.sh --scenario log_volume`.
10. Clean up: `unset OLD_OS OLD_API`; `rm env.sum`.

## Expected outcome

1. The build reports `OK - generated unique credentials in .env: ...` naming at least `INDEXER_DASHBOARD_PASSWORD`, `OS_PASS` and `WAZUH_AUTH_PASS`, and `OK - wrote .radar-generated/internal_users.yml and wazuh.yml`, and ends with `=== SUCCESS ...`. `.env` has mode 600 and `.radar-generated` mode 700, holding `internal_users.yml`, `wazuh.yml` and `.gitignore`. `internal_users.yml` holds bcrypt hashes only.
2. 200 for the generated `OS_PASS`, 401 for `SecretPassword`, 200 for the generated `WAZUH_AUTH_PASS`, 401 for the stock API password, 401 for the demo user `readall`. The dashboard login succeeds.
3. The build reports `OK - existing deployment (..._wazuh-indexer-data found): passwords left unchanged`; `sha256sum -c` reports `OK`.
4. The build completes without error.
5. Without `sudo`: `ERROR: rotate-credentials needs root (docker compose, bind mounts). Re-run with sudo.` and exit status 1. With the indexer stopped: `[ERROR] container wazuh.indexer is not running; start the core stack first`, a non-zero exit status, and `.env` unchanged (`OK`).
6. The output shows `OK - indexer users rotated; .env updated (previous copy: .radar-state/env.before-rotation)`, the stack being recreated, the Wazuh API and OpenSearch becoming reachable, `Refreshing active_responses.env...` and `=== Credentials rotated. ...`; exit status 0.
7. 200 for the new `OS_PASS`, 401 for the old one; 200 for the new `WAZUH_AUTH_PASS`, 401 for the old one. The checksum of `.radar-state/env.before-rotation` equals the one in `env.sum`, and its mode is 600. The dashboard login with the new password succeeds.
8. `root:wazuh 440`, and `grep` exits 0: the manager's active-response environment carries the new indexer password.
9. No line of the Wazuh API section reports `Authentication failed`, the core daemons are reported running, and the OpenSearch check reports `OK - OpenSearch reachable (cluster: ...)`. A `FAIL` for agents in `log_volume`'s group is expected, as no endpoint is enrolled.

The test passes when every expected outcome is observed.
