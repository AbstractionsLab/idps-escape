# SONAR container image content, dependencies and mounts

No automated test covers the image; this test inspects the build files (`sonar/Dockerfile.sonar`, `sonar/Dockerfile.sonar.dockerignore`, `sonar/sonar.sh`, `sonar/wazuh/docker-compose.sonar.yml`) and then builds and examines the image.

## Preconditions and setup actions

1. A repository checkout; all commands run from its root.
2. Docker 23 or later, whose default builder is BuildKit (`docker buildx version` succeeds). The build downloads the `python:3.10.12` base image and the Python packages, so it needs network access to Docker Hub and PyPI; no Wazuh deployment is needed.
3. No image or container named `sonar:v0.8` / `sonar-container` that must be kept. Step 9 retrains the host's `sonar/models/linux_resource_monitoring` model, replacing an existing one; the host's `sonar/models/` must be writable by uid 1000 (the image's user), and the step needs an interactive terminal (`sonar/sonar.sh` runs `docker run -it`).

## Test steps

**Inspection**

1. Show the build instructions: `grep -nE '^(FROM|USER|COPY|RUN|ENTRYPOINT|CMD)' sonar/Dockerfile.sonar`.
2. Show the build-context rules: `grep -vE '^\s*(#|$)' sonar/Dockerfile.sonar.dockerignore`.
3. Show the mounts: `grep -n -- '-v \|_VOLUME=' sonar/sonar.sh` and `grep -nA14 '^  sonar:' sonar/wazuh/docker-compose.sonar.yml`.

**Build and examination**

4. Plant canary files that must not reach the image:
   ```
   mkdir -p sonar/payloads sonar/models/state
   touch sonar/.env sonar/canary.pkl sonar/payloads/canary.json sonar/models/state/canary-tst088.json
   ```
5. Build the image: `docker build -f sonar/Dockerfile.sonar -t sonar:v0.8 .`
6. List the project directory and search it for excluded paths:
   ```
   docker run --rm --entrypoint sh sonar:v0.8 -c 'ls -A /home/alab/soar /home/alab/soar/adbox; find /home/alab/soar \( -name .env -o -name "*.pkl" -o -path "*/sonar/payloads*" -o -path "*/sonar/models/state*" -o -path "*/adbox/assets*" -o -name __pycache__ \)'
   ```
7. List the installed packages: `docker run --rm --entrypoint poetry sonar:v0.8 run pip list --format=freeze`.
8. Show the user, entry point and command: `docker image inspect sonar:v0.8 --format '{{.Config.User}} {{.Config.Entrypoint}} {{.Config.Cmd}}'`, then run `docker run --rm sonar:v0.8; echo "exit $?"`.
9. Run a debug scenario through the wrapper script: `sonar/sonar.sh scenario --use-case sonar/scenarios/linux_resource_monitoring.yaml --debug`, then `ls sonar/models/linux_resource_monitoring/`.

## Cleanup

`rm -f sonar/.env sonar/canary.pkl sonar/payloads/canary.json sonar/models/state/canary-tst088.json`, and remove `sonar/payloads/` and `sonar/models/state/` if step 4 created them.

## Expected outcome

1. Step 1: the base image is `python:3.10.12`; a user is created and `USER ${user}` (with `ENV user=alab`) precedes the installs; the only `COPY` sources are `pyproject.toml poetry.lock README.md`, `sonar` and `adbox/__init__.py` (no `COPY .`); the installs are `poetry install --only main,sonar --no-root` and `poetry install --only-root`; the entry point is `["poetry", "run", "sonar"]` and the command `["--help"]`.
2. Step 2: the first rule is `*`; the only re-included paths are `pyproject.toml`, `poetry.lock`, `README.md`, `sonar` and `adbox/__init__.py`; `**/.env`, `**/*.pkl`, `sonar/payloads`, `sonar/models/state`, `**/__pycache__` and `**/.DS_Store` are excluded.
3. Step 3: `sonar/sonar.sh` mounts `sonar/models`, `sonar/test_data`, `sonar/scenarios` and `sonar/default_config.yaml` at the same paths under `/home/alab/soar/sonar/`, and `${SONAR_ANOMALIES_DIR:-/srv/sonar/anomalies}` at `/var/log/sonar`; the compose service `sonar` mounts the anomaly directory, `sonar/models`, `sonar/scenarios` and `sonar/default_config.yaml` (read-only).
4. Step 5: the build succeeds.
5. Step 6: `/home/alab/soar` lists exactly `README.md`, `adbox`, `poetry.lock`, `pyproject.toml` and `sonar`; `adbox` holds only `__init__.py`; the `find` command prints nothing, so none of the canaries is in the image.
6. Step 7: the list contains `time-series-anomaly-detector==0.4.0`, `torch==2.3.0`, `opensearch-py==3.0.0` and `pandas==2.2.2`, and none of `tabulate`, `more-itertools`, `ansible-core`, `selenium`, `scapy`, `faker`, `geoip2`, `pytest-cov`, `pytest-mock`, `doorstop`.
