# SONAR detection window, severity threshold and no alert writes

## Preconditions and setup actions

1. SONAR dependencies installed: `poetry install --with adbox,radar,test`.

## Test steps

1. From the repository root, run:
   ```
   poetry run pytest tests/sonartests/test_detection_cli.py tests/sonartests/test_wazuh_and_pipeline.py tests/sonartests/test_scenario.py -v
   ```

## Expected outcome

1. With 5-minute buckets, a 60-minute detection period yields exactly 12 verdicts, from the first bucket of the period to the last complete bucket; alerts are fetched from the period start minus the model's context; the bucket still filling is never reported.
2. Reported documents carry the model name, every model column as feature names and feature count, the model's sliding window and bucket size, the severity as `anomaly_score`, and each contributor's value in the bucket.
3. A threshold selects buckets by severity, independently of the raw score; a threshold outside [0, 1] is rejected both by the post-processor and when a scenario is loaded.
4. One-shot detection returns 0 when the period was scored, 2 without alerts or with too few buckets, and 1 on a model error or a missing model; `sonar detect` with and without a scenario uses the same detection path.
5. The indexer client has no method to write alerts, the former synthetic-fill CLI options are rejected, and the former synthetic-fill scenario keys are reported as obsolete.
