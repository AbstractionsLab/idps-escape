# SONAR refuses to persist untrained models

## Preconditions and setup actions

1. SONAR dependencies installed: `poetry install --with adbox,radar,test`. The real MVAD library (`time-series-anomaly-detector` 0.4.0) is installed.

## Test steps

1. From the repository root, run the training pre-flight unit tests:
   ```
   poetry run pytest tests/sonartests/test_engine_and_features.py -k "Engine" -v
   ```
2. Run the tests against the real MVAD library:
   ```
   poetry run pytest tests/sonartests/test_engine_real_mvad.py -v
   ```
3. With the default configuration (`sliding_window: 200`, library batch size 128 and stride 10), train on 288 five-minute buckets, and observe the result.

## Expected outcome

1. Training on 288 buckets with the default window fails with `InsufficientTrainingDataError`, names the required bucket count (1725), never calls the library's `fit`, and leaves no model.
2. For each tested dataset size, the predicted number of optimiser updates equals the number of `Adam.step` calls the library performs, including the case of zero updates.
3. A trained model's network parameters differ from the library's initialisation, and the saved model records `gradient_steps` greater than zero, which survives saving and loading.
4. An unknown training parameter such as `learning_rate` is rejected with a hint to use `lr`.
5. No library checkpoint is written to the working directory, and two training runs use different checkpoint directories.
6. The library defaults and configuration fields that SONAR copies match the installed library.
