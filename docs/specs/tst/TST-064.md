# SONAR feature schema 2 and feature contract

## Preconditions and setup actions

1. SONAR dependencies installed: `poetry install --with adbox,radar,test`.

## Test steps

1. From the repository root, run:
   ```
   poetry run pytest tests/sonartests/test_features_v2.py -v
   ```

## Expected outcome

1. One failed login and two hundred failed logins in a bucket give `alert_count`, `is_auth_failure` and category counts of 1 and 200.
2. Alerts at 00:01, 00:05 and 00:21 with 5-minute buckets give rows for 00:00, 00:05, 00:10, 00:15 and 00:20, the empty ones with zero counts. An explicit window adds leading and trailing empty buckets; a window given only an end starts at the first alert.
3. A numeric field present on 10 of 100 alerts in a bucket yields the mean of those 10 values. Empty buckets are filled with 0, or with the previous value under `numeric_fill: ffill`.
4. A category unseen in training is counted in `<field>__other` at detection, with columns identical to training.
5. The model records its feature configuration, vocabulary and columns. Predicting on differing columns fails and names them. Loading a model with feature schema 1, or without metadata, fails with a request to retrain. Changed scenario feature settings produce a warning and the model's settings are used.
