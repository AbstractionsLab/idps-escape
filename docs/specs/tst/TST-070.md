# SONAR evaluation metrics, calibration and `sonar evaluate`

## Preconditions and setup actions

1. SONAR dependencies installed: `poetry install --with sonar,test`.

## Test steps

1. From the repository root, run:
   ```
   poetry run pytest tests/sonartests/test_evaluation.py -v
   ```
2. Generate the labelled splits with `generate_resource_data.py --evaluation` and `generate_attack_data.py --evaluation`, and run `sonar evaluate` with calibration for each bundled scenario and each backend (`mvad`, `pca`, `ewma`), as listed in `docs/specs/trp/assets/sonar-evaluation/README.md`.

## Expected outcome

1. For known detections and labels, the event counts, true and false alarms, precision, recall, F1, mean delay and false alarms per day are the hand-computed values; touching reported buckets form one alarm; a tolerance widens the event windows; an alarm before an event has zero delay.
2. Threshold and minimum run length select reported buckets with the same rule as detection.
3. Events of types not counted are ignored with the alarms on them; events outside the scored span are not counted; detections outside the labelled span are ignored.
4. Calibration picks the least filtering that reaches the best F1 within the false-alarm budget, and reports when no setting stays within it.
5. Label files round-trip and invalid ones are refused; OpenSearch anomaly detection results (including a `_search` response with failed intervals) and generic JSON-lines records load as detections.
6. `sonar evaluate` writes a JSON report and a Markdown summary with the configured, validation and test runs and the anomaly confidence; it refuses inconsistent inputs; with a scenario and the `ewma` backend it trains, scores the test file and detects the labelled spike.
7. The generators write training, validation and test files with label files whose events lie inside each split's span after its context, and the same seed gives the same files.
8. Every scenario and backend gets a JSON report and a Markdown summary with configured, validation and test runs; calibration states whether it stayed within the false-alarm budget, and the reported anomaly confidence equals the calibrated test precision.
