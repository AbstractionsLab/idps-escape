# GUI: Build & validate `geoip_detection` scenario

## Preconditions and setup actions
- Same as [TST-055](./TST.html#TST-055) (including the MaxMind GeoLite2 license key precondition — `geoip_detection` needs it too).

## Test steps

1. On the controller host, prepare `.env`:
```bash
cd radar
cp env.example .env
```
Edit it with the values described in Preconditions (see [TST-055](./TST.html#TST-055)).

2. Start the GUI:
```bash
./radar.sh gui
```
This creates a Python virtual environment and installs dependencies automatically on first run. Open the GUI in a browser at the printed host:port.

3. In the GUI, go to **Deployment → Scenario Management** (default **Deploy scenario** sub-tab), select scenario `geoip_detection`, and click **Deploy**. If prompted for the sudo password, enter it.

4. In the GUI, go to **Deployment → Agent Management** (default **Onboard agent** sub-tab). Select scenario `geoip_detection`, click **Mint token**, and copy the printed `bootstrap-agent.sh` command.

5. On the agent host, download the `bootstrap-agent.sh` script and run the copied command exactly as printed, or by adding an `--agent-name` argument, under `sudo`:
```bash
scp bootstrap-agent.sh <user>@<agent-host>:~/
ssh <user>@<agent-host>
chmod +x bootstrap-agent.sh
```

6. In the GUI, go to **Deployment → Group Management**. Enter the agent's IP/name, select scenario `geoip_detection`, and click **Assign group**.

7. Check health of manager: in **Deployment → Status**, choose the GeoIP Detection scenario and press **Run health check**.

8. Copy the simulation script to the agent host and run it directly there:
```bash
scp radar-test-framework/simulate/scenarios/geoip_detection.py <user>@<agent-host>:~/
ssh <user>@<agent-host>
sudo python3 geoip_detection.py
```
This script is fully standalone.

9. (Optional) If DECIPHER is configured, open Flowintel in browser.

## Expected outcome

1. `.env` exists in the controller with the required variables set, including `MAXMIND_LICENSE_KEY`.

2. The GUI is reachable in a browser, and the **Deployment** page shows **Scenario Management**, **Agent Management**, and **Group Management** tabs all present.

3. Two items to verify:

   - (a) The command completes with `=== SUCCESS` in its output.

   - (b) Confirm the GeoLite databases were downloaded:
```bash
docker exec -it wazuh.manager bash -c 'ls -l /var/ossec/etc/radar/GeoLite2-*'
```
Both `GeoLite2-City.mmdb` and `GeoLite2-ASN.mmdb` should be present.

4. A ready-to-run command of the form `sudo ./bootstrap-agent.sh --manager <address> --token <token> --group default --group geoip_detection --group radar_shared` is printed.

5. The command completes with `=== SUCCESS ===` in its output.

6. On the Wazuh Dashboard, open **Agents management → Summary**. The agent should be assigned groups `geoip_detection` and `radar_shared`.

7. No `FAIL` lines should be present in the health check.

8. Two items to verify:

   - (a) `geoip_detection.py` is copied and runs on the agent host without error, printing "geoip_detection simulation completed".

   - (b) Tail manager logs in a separate terminal:
```bash
docker exec -it wazuh.manager bash -c 'tail -F /var/ossec/logs/ossec.log /var/ossec/logs/active-responses.log /var/ossec/logs/radar/enrichment_errors.log'
```
Within 2 minutes, confirm:

   - Rule `100900` (and/or `100901`) appears in Wazuh Dashboard (**Discovery**).
   - `radar_ar.py` wrote an active-response entry to `active-responses.log`.
   - An email notification is delivered (check the SMTP relay logs or destination inbox).
   - `enrichment_errors.log` has no new entries.

9. (Optional) Items to verify:

    - (a) A FlowIntel case is created and can be accessed at the Flowintel URL included in the email notification.

    - (b) The FlowIntel case contains relevant information about the event, related events found in MISP, and a breakdown of the risk score including the assigned tier.


## Cleanup

1. After finishing tests, clean up using **Deployment → Teardown** in the GUI.

2. To clean agent host:
```bash
scp uninstall-agent.sh <user>@<agent-host>:~/
ssh <user>@<agent-host>
chmod +x uninstall-agent.sh
sudo ./uninstall-agent.sh --purge-data
```
