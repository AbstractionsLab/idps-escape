# GUI: Build & validate `suspicious_login` scenario

## Preconditions and setup actions
- A controller host/node is available:
    - A Linux machine/VM is available to the tester.
    - OS: recent GNU/Linux distribution, preferably an Ubuntu distribution (22.04+).
- A second test node (accessible via the controller node) is available: GNU/Linux distro e.g. Debian GNU/Linux 13 (trixie).
    - Python must be installed on this node.
- Targeted Wazuh manager and agent versions: `4.14.1`.
- The values needed for `.env` are available. See `env.example` — each variable has a comment explaining what it's for and exactly what format/value it needs. At minimum for this scenario: `OS_URL`/`OS_USER`/`OS_PASS`, `WAZUH_API_URL`/`WAZUH_AUTH_USER`/`WAZUH_AUTH_PASS`, `WAZUH_MANAGER_ADDRESS`, and `MAXMIND_LICENSE_KEY` (see below).
- A MaxMind GeoLite2 license key is available (used by the manager to download the GeoIP databases needed for this scenario's own enrichment — country, region, city, ASN, velocity):
    - Create a free MaxMind account at [MaxMind GeoLite2 sign-up](https://www.maxmind.com/en/geolite2/signup).
    - Once logged in, go to the account's **My License Key** page and generate a new license key.
    - Keep this key ready to paste into `.env` as `MAXMIND_LICENSE_KEY` in the test steps below. Note that MaxMind's own sign-up flow may change over time — if the linked page doesn't match, use MaxMind's current account/license-key management page instead.
- The DECIPHER Stack (DECIPHER, FlowIntel and MISP) is deployed and reachable from the Wazuh manager. The validated version is available in the [DECIPHER folder of the SATRAP-DL repository](https://github.com/AbstractionsLab/satrap-dl/tree/main/decipher), tested against `v1.0` of SATRAP-DL. Once deployed, configure the `DECIPHER_BASE_URL` variable in `.env` to point to the running DECIPHER instance.
- Regarding the environment variables set in `.env`:
    1. Confirm the variable is actually set in *this* shell: `env | grep OS_URL`

    2. If empty, set it explicitly and retest, e.g. `export OS_URL="https://<your-opensearch-host-IP>:9200"`, `export OS_USER="admin"`, `export OS_PASS="SecretPassword"`

    3. Retest: `curl -u "$OS_USER:$OS_PASS" -k "$OS_URL/_index_template/radar-log-volume?pretty"`

### Optional: test the full pipeline including integration with DECIPHER

- Bring the DECIPHER stack up following the corresponding steps in [DECIPHER TST-021](https://abstractionslab.github.io/satrap-dl/traceability/TST.html#TST-021)
- Configure the DECIPHER setting as per the setup actions in [DECIPHER TST-022](https://abstractionslab.github.io/satrap-dl/traceability/TST.html#TST-022)

## Test steps

1. On the controller host, prepare `.env`:
```bash
cd radar
cp env.example .env
```
Edit it with the values described in Preconditions above.

2. Start the GUI:
```bash
./radar.sh gui
```
This creates a Python virtual environment and installs dependencies automatically on first run. Open the GUI in a browser at the printed host:port.

3. In the GUI, go to **Deployment → Scenario Management** (default **Deploy scenario** sub-tab), select scenario `suspicious_login`, and click **Deploy**. If prompted for the sudo password, enter it.

4. In the GUI, go to **Deployment → Agent Management** (default **Onboard agent** sub-tab). Select scenario `suspicious_login`, click **Mint token**, and copy the printed `bootstrap-agent.sh` command.

5. On the agent host, download the `bootstrap-agent.sh` script and run the copied command exactly as printed, or by adding an `--agent-name` argument, under `sudo`:
```bash
scp bootstrap-agent.sh <user>@<agent-host>:~/
ssh <user>@<agent-host>
chmod +x bootstrap-agent.sh
```

6. In the GUI, go to **Deployment → Group Management**. Enter the agent's IP/name, select scenario `suspicious_login`, and click **Assign group**.

7. Check health of manager: in **Deployment → Status**, choose the Suspicious Login scenario and press **Run health check**.

8. Copy the simulation script to the agent host and run it directly there:
```bash
scp radar-test-framework/simulate/scenarios/suspicious_login.py <user>@<agent-host>:~/
ssh <user>@<agent-host>
sudo python3 suspicious_login.py
```
This script is fully standalone.

## Expected outcome

1. `.env` exists in the controller with the required variables set, including `MAXMIND_LICENSE_KEY`.

2. The GUI is reachable in a browser, and the **Deployment** page shows **Scenario Management**, **Agent Management**, and **Group Management** tabs all present. On first run, a `.venv` directory is created under the RADAR root.

3. Two items to verify:
    - (a) The command completes with `=== SUCCESS` in its output.

    - (b) Confirm the GeoLite databases were downloaded:

```bash
    docker exec -it wazuh.manager bash -c 'ls -l /var/ossec/etc/radar/GeoLite2-*'
```

Both `GeoLite2-City.mmdb` and `GeoLite2-ASN.mmdb` should be present.

4. A ready-to-run command of the form `sudo ./bootstrap-agent.sh --manager <address> --token <token> --group default --group suspicious_login` is printed.

5. The command completes with `=== SUCCESS ===` in its output.

6. On the Wazuh Dashboard, open **Agents management → Summary**. The agent should be assigned groups `suspicious_login` and `radar_shared`.

7. No `FAIL` lines should be present in the health check.

8. Three items to verify:
    - (a) `suspicious_login.py` is copied and runs on the agent host without error, printing "suspicious_login simulation completed".

    - (b) Tail manager logs in a separate terminal (within 1 minute, confirm authentication events enriched with RADAR columns appear in the log): `docker exec -it wazuh.manager bash -c 'tail -F /var/ossec/logs/radar/enriched_auth.log'`

    - (c) A Wazuh rule for suspicious login `210***` appears in Wazuh Dashboard (**Discovery**).

## Cleanup

1. After finishing tests, clean up using **Deployment → Teardown** in the GUI. In the event that the GUI teardown fails, you can use the following command on the server host:

```bash
    docker compose -f docker-compose.core.yml -f docker-compose.webhook.yml -f volumes.yml down -v --remove-orphans
```

2. To clean agent host:

```bash
    scp uninstall-agent.sh <user>@<agent-host>:~/
```

```bash
    ssh <user>@<agent-host>
```

```bash
    chmod +x uninstall-agent.sh
```

```bash
    sudo ./uninstall-agent.sh --purge-data
```
