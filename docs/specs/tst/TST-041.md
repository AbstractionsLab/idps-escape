# Setup RADAR foundation

This test brings up the RADAR foundation on a clean host: the Wazuh core stack (manager, indexer, dashboard) with per-deployment credentials and hardened agent enrollment, without any RADAR scenario applied. The scenario tests (TST-055 to TST-062) start from this state.

## Preconditions and setup actions
- A RADAR host is available to the tester:
    - OS: recent GNU/Linux distribution, preferably Ubuntu 22.04+.
    - Docker Engine 20.10+ and the Docker Compose plugin are installed (`docker --version`, `docker compose version`).
    - The tester has `sudo` on the host, and enough disk is available under `/srv/wazuh/` for the indexer.
    - The repository is checked out on the host, and no Wazuh manager container is running yet.
- Targeted Wazuh manager and agent versions: `4.14.1`.
- SMTP credentials are available to the tester (`SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `EMAIL_TO`).
- The DECIPHER Stack (DECIPHER, FlowIntel and MISP) is deployed and reachable from the RADAR host. The validated version is available in the [DECIPHER folder of the SATRAP-DL repository](https://github.com/AbstractionsLab/satrap-dl/tree/main/decipher), tested against `v1.0` of SATRAP-DL. Once deployed, its address is set as `DECIPHER_BASE_URL` in `.env` (step 2).

## Test steps

1. On the RADAR host, the working directory is required to be `radar`:
```bash
cd radar
```

2. Create `.env` from the template and fill it in:
```bash
cp env.example .env
```
Each variable in `env.example` is commented. Set the addresses (`OS_URL`, `DASHBOARD_URL`, `WAZUH_API_URL`, `WAZUH_MANAGER_ADDRESS`, `WEBHOOK_URL`), the users, the SMTP values and `DECIPHER_BASE_URL`. Leave `OS_PASS`, `DASHBOARD_PASS` and `WAZUH_AUTH_PASS` empty: the first deployment generates them.

3. Bring up the plain Wazuh stack:
```bash
sudo ./build-radar.sh --core-only
```
(Equivalent in the GUI: **Deployment → Scenario Management → Deploy scenario** with **Plain Wazuh only**.)

4. Check the containers, certificates and generated credentials:
```bash
docker ps --format '{{.Names}}\t{{.Status}}'
ls config/wazuh_indexer_ssl_certs/
grep -E '^(OS_PASS|WAZUH_AUTH_PASS|DASHBOARD_PASS|WAZUH_CLUSTER_KEY)=' .env | cut -d= -f1
```

5. Check that agent enrollment is hardened:
```bash
sudo ./radar.sh enrollment status
sudo grep -E '<use_password>|<purge>' /srv/wazuh/manager/etc/ossec.conf
```

6. Load the generated indexer credentials and query the indexer:
```bash
for v in OS_URL OS_USER OS_PASS; do export "$v=$(PYTHONPATH=. python3 -m wazuh_api.envfile get "$v")"; done
curl -sk -u "$OS_USER:$OS_PASS" "$OS_URL/_cluster/health?pretty"
```

## Expected outcome
1. The working directory is `radar`.

2. `.env` exists with the required variables set.

3. The command completes with `=== SUCCESS: plain Wazuh manager/indexer/dashboard is up (no RADAR scenario applied) ===`.

4. Three items to verify:
    - `wazuh.manager`, `wazuh.indexer` and `wazuh.dashboard` are listed as `Up`.
    - `config/wazuh_indexer_ssl_certs/` contains the generated `.pem` files.
    - `OS_PASS`, `WAZUH_AUTH_PASS` and `DASHBOARD_PASS` are set in `.env`, with values other than the stock Wazuh demo passwords, and `WAZUH_CLUSTER_KEY` is set.

5. The window status is `CLOSED - port 1515 is blocked`, and `ossec.conf` contains `<use_password>yes</use_password>` and `<purge>no</purge>`.

6. The indexer answers with the generated credentials, and its cluster `status` is `green` or `yellow`.
