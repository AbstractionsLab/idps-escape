# GUI: Build & validate `scanning_detection` scenario

## Preconditions and setup actions
- Same as [TST-055](./TST.html#TST-055). Ensure the Apache/Nginx log sources are configured on the agent host that will be targeted by the simulation.

### Optional: test the full pipeline including integration with DECIPHER

- Bring the DECIPHER stack up following the corresponding steps in [DECIPHER TST-021](https://abstractionslab.github.io/satrap-dl/traceability/TST.html#TST-021)
- Configure the DECIPHER setting as per the setup actions in [DECIPHER TST-022](https://abstractionslab.github.io/satrap-dl/traceability/TST.html#TST-022)

## Test steps

1. On the controller host, prepare `.env`:
```bash
cd radar
cp env.example .env
```
Edit it with the values described in Preconditions (see [TST-055](./TST.html#TST-055)).

2. Start the GUI:
```bash
./radar.sh gui
```
This creates a Python virtual environment and installs dependencies automatically on first run. Open the GUI in a browser at the printed host:port.

3. In the GUI, go to **Deployment → Scenario Management** (default **Deploy scenario** sub-tab), select scenario `scanning_detection`, and click **Deploy**. If prompted for the sudo password, enter it.

4. In the GUI, go to **Deployment → Agent Management** (default **Onboard agent** sub-tab). Select scenario `scanning_detection`, click **Mint token**, and copy the printed `bootstrap-agent.sh` command.

5. On the agent host, download the `bootstrap-agent.sh` script and run the copied command exactly as printed, or by adding an `--agent-name` argument, under `sudo`:
```bash
scp bootstrap-agent.sh <user>@<agent-host>:~/
ssh <user>@<agent-host>
chmod +x bootstrap-agent.sh
```

6. In the GUI, go to **Deployment → Group Management**. Enter the agent's IP/name, select scenario `scanning_detection`, and click **Assign group**.

7. Check health of manager: in **Deployment → Status**, choose the Scanning Detection scenario and press **Run health check**.

8. Copy the simulation script to the agent host and run it directly there:
```bash
scp radar-test-framework/simulate/scenarios/scanning_detection.py <user>@<agent-host>:~/
ssh <user>@<agent-host>
sudo python3 scanning_detection.py
```
This script is fully standalone. It runs interactively by default: after each case it prints a hint block (source IP, time window, and the exact rule IDs expected present/absent), then pauses and waits for `[y]es / [n]ot yet / [q]uit` before moving to the next case, check the dashboard for that case before answering.

To check what the script actually sent for a given case, use the `wazuh-archives-*` index in **Discover**. It captures every analyzed event, alert or not, which is useful for confirming an "expect absent" line in the hint. If that index pattern does not exist yet, create it once via **Dashboards Management → Index Patterns → Create index pattern**, matching `wazuh-archives-*` in Wazuh Dashboard.

9. (Optional) If DECIPHER is configured, open Flowintel in browser.

## Expected outcome

1. `.env` exists in the controller with the required variables set.

2. The GUI is reachable in a browser, and the **Deployment** page shows **Scenario Management**, **Agent Management**, and **Group Management** tabs all present. On first run, a `.venv` directory is created under the RADAR root.

3. Two items to verify:

    - (a) The command completes with `=== SUCCESS` in its output.

    - (b) Confirm the manager applied the scanning_detection config:

```bash
docker exec -it wazuh.manager cat /var/ossec/etc/ossec.conf | grep -A3 "RADAR: scanning_detection"
```

The marked block should be present.

4. A ready-to-run command of the form `sudo ./bootstrap-agent.sh --manager <address> --token <token> --group default --group scanning_detection` is printed.

5. The command completes with `=== SUCCESS ===` in its output.

6. On the Wazuh Dashboard, open **Agents management → Summary**. The agent should be assigned group `scanning_detection`.

7. No `FAIL` lines should be present in the health check.

8. Three items to verify:

    - (a) `scanning_detection.py` is copied and runs on the agent host without error. It pauses after each case for confirmation — answer `y` for every case (after checking the dashboard) to reach the end; it then prints "scanning_detection simulation completed".

    - (b) Within 2 minutes, scanning rules appear in Wazuh Dashboard (**Discovery**) for each case's `present` rule IDs.

    - (c) For cases with an `absent` expectation, cross-check `wazuh-archives-*` in **Discover** (create the index pattern first via **Dashboards Management → Index Patterns** if it is not there yet), confirm the raw event was received by the manager but the listed rule ID(s) genuinely never fired.

    - (d) Receive an email notification in cases where rule ID `100830` is expected to be triggered. The body includes, among other fields: `Context events` (the count of correlated indicator events found for this specific source IP within the confirmation window — should be 2 or more, not 0, for a `confirm_*` case), `Scenario details` (the scanning-specific `scan_src_ip`/`uri`/`http_method`/`user_agent` extracted from those events, not the generic `IOCs` line above it), `CTI score (T)`, `CTI labels`, and `Identified scanners`.

9. (Optional) Items to verify:

    - (a) One or two FlowIntel cases may be created per confirmed scan: RADAR's own incident (tier ≥ 1, linked in the email's `FlowIntel case`/`Case URL`).

    - (b) Open the case linked in the email and confirm its description contains: source metadata (`source`, `decision_id`, scenario/detection type, originating rule); a risk breakdown matching the email's `Components` line (score, tier, anomaly/signature/CTI sub-components); an `iocs` section plus, for `scanning_detection`, an `extras` section (`scan_src_ip`/`uri`/`http_method`/`user_agent`) matching the email's `Scenario details`; `misp_events`.

    - (c) The description also contains the elements `misp_events` and `identified_scanners`, either carrying information or an empty value.

    - (d) If the value for `misp_events` is a non-empty list, the `CTI score (T)` is non-zero.


## Cleanup

1. After finishing tests, clean up using **Deployment → Teardown** in the GUI.

2. To clean agent host:
```bash
scp uninstall-agent.sh <user>@<agent-host>:~/
ssh <user>@<agent-host>
chmod +x uninstall-agent.sh
sudo ./uninstall-agent.sh --purge-data
```
