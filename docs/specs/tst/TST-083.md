# RADAR health check scoping

No automated test covers the health check scripts; this test is run by hand against a deployment.

## Preconditions and setup actions

- A RADAR host with `radar/.env`, `sudo`, and the core stack and `log_volume` deployed with `sudo ./build-radar.sh log_volume`. No other scenario is deployed.
- One endpoint, `endpoint-a`, enrolled with `bootstrap-agent.sh` in groups `default` and `log_volume` and connected ([TST-082](./TST.html#TST-082)).
- `WEBHOOK_URL` is set in `radar/.env`. The user running the checks can use Docker (member of the `docker` group).
- All commands run in `radar/` on the RADAR host. Record each command's exit status with `echo $?`.

## Test steps

1. **Baseline** (for step 4): `docker exec wazuh.manager sh -c 'sha256sum /var/ossec/etc/ossec.conf /var/ossec/etc/shared/*/agent.conf /var/ossec/etc/rules/*.xml'` and `docker exec wazuh.manager /var/ossec/bin/manage_agents -l`; save both outputs.
2. **Single scenario with agent**: `./health-radar.sh --scenario log_volume --agent-name endpoint-a`.
3. **Other scenario**: `./health-radar.sh --scenario suspicious_login`.
4. **All scenarios**: `./health-radar.sh`. Then repeat the two commands of step 1 and compare.
5. **Unknown agent**: `./health-radar.sh --scenario log_volume --agent-name endpoint-a,no-such-agent`.
6. **Missing scenario parts**: `./radar_deploy/manager-undo-scenario.sh log_volume`, then `./health-radar.sh --scenario log_volume`. Redeploy with `sudo ./build-radar.sh log_volume` and reassign the agent: `./radar_deploy/manager-assign-agent-group.sh --scenario log_volume --agent-name endpoint-a`.
7. **Expired token exception**: `sudo ./radar.sh mint-token default 1`, then `sudo systemctl stop radar-token-revoke.timer` so that the revocation is missed; wait two minutes; `ls .radar-state/`; `./health-radar.sh --scenario log_volume`; `ls .radar-state/` again.
8. **No registered manager**: `cp infra.yaml infra.yaml.bak && printf 'components: {}\n' > infra.yaml`; `./health-radar.sh --scenario log_volume`; then `mv infra.yaml.bak infra.yaml`.
9. **GUI**: in the GUI, Deployment page, Status tab, run the check for `log_volume` with agent `endpoint-a`.

## Expected outcome

1. Outputs saved.
2. Exit status 0. The sections print in the order `=== MANAGER (filesystem/container) ===`, `=== MANAGER (Wazuh API / OpenSearch / webhook) ===`, `=== AGENTS ===`, each line starting with `OK`, `WARN`, `FAIL` or `SKIP`, and no `FAIL`. The first section has a `--- <node> ---` block for each manager node in `infra.yaml`, includes `log_volume pipeline patch present` and the webhook reachability from the indexer container, and has no `maxminddb` or enrichment lines. The second section reports the core daemons running, `log_volume active-response wiring`, the `log_volume` group configuration, `a1-log-volume.xml` and its decoders, one agent assigned to all of `log_volume`'s groups, the OpenSearch cluster status and the `radar-log-volume` index template. The agent section reports `endpoint-a` active and in `default` and `log_volume`.
3. The first section adds the framework Python, `maxminddb`, enrichment file, GeoLite2, state store and error log checks and has no `log_volume` pipeline line. The second section reports `FAIL` for the `suspicious_login` wiring, group configuration, `a3-suspicious-login.xml` and the agents, and no `log_volume` template line. There is no agent section.
4. Checks for every scenario in `radar/config.yaml` appear, including the `geoip_detection` `whitelist_countries` check; the scenarios that are not deployed report `FAIL`. The checksums and the agent list are identical to step 1.
5. `OK` lines for `endpoint-a`, and `FAIL - agent no-such-agent not found via API` for both the status and the group check.
6. The second section reports `FAIL` for the `log_volume` wiring, the `log_volume` group configuration, `a1-log-volume.xml` and the agents of `log_volume`. After redeployment, step 2 passes again.
7. Before the check, `enrollment-token.expires` exists. The first section starts with `WARN - enrollment token expired at ... and was still active; revoking now` and `OK - enrollment token revoked on wazuh.manager`; afterwards the file is gone.
8. The run stops after the first section with a non-zero exit status; no API or agent section is printed.
9. The same three sections stream into the page, in the same order, with the same results as step 2.

The test passes when every expected outcome is observed.
