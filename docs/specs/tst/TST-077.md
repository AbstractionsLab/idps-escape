# RADAR: off-hours marking, configuration and deployment logic

## Preconditions and setup actions

- Same generic preconditions as [TST-055](./TST.html#TST-055).
- `poetry install --with radar,test`.
- For step 3, a running Wazuh indexer reachable as `OS_URL` (credentials in `radar/.env`).

## Test steps

1. From `radar/`, run `tests/run-tests.sh`, or only `PYTHONPATH=anomaly_detector:. poetry run pytest tests/py/test_off_hours.py tests/py/test_suspicious_login_ingest.py tests/py/test_ad_alerts_webhook.py tests/py/test_filebeat_pipeline.py`.
2. From `radar/anomaly_detector/`, run `poetry run python off_hours.py validate --config ../config.yaml`.
3. From `radar/`, run `poetry run python radar-test-framework/checks/off_hours_simulate.py --env .env`.

## Expected outcome

1. All tests pass. In particular:
   - every case of the shared table gives the expected flag, group and user (including midnight-crossing shifts, summer time, upper-case names, unknown and ignored users, and unreadable times);
   - each invalid input of SRS-062 requirement 1 is rejected with a message naming it;
   - the rule-mode query reports a long session once and again after the quiet period;
   - the rendered rule-mode message gives a webhook line with `off_hours_count` and `schedule_group`, while other AD lines are unchanged;
   - the model-mode detector uses only model-mode groups, `sum(radar.off_hours)` and no imputation;
   - redeploying replaces stale monitors and detectors in place and stops the previous detectors;
   - the synthetic history marks no shift event as off hours except trent's evenings and burst.
2. The command logs `valid` with the rule-mode and model-mode groups.
3. The script prints `PASS` for every case and ends with `[ok]`: the Painless pipeline and the Python implementation agree on the deployed cluster.
