# SONAR at-most-once anomaly delivery and realtime resilience

## Preconditions and setup actions

1. SONAR dependencies installed: `poetry install --with adbox,radar,test`.

## Test steps

1. From the repository root, run:
   ```
   poetry run pytest tests/sonartests/test_realtime_delivery.py tests/sonartests/test_detection_cli.py -v
   ```

## Expected outcome

1. The anomaly identifier is the same for the same scenario and bucket, whatever the time zone of the timestamp, and differs between scenarios and between buckets; every anomaly document carries it.
2. The watermark file survives a new process, never moves back, is separate per scenario, and an unreadable file is treated as no watermark.
3. Two polls over the same data deliver each anomaly once, and a restart delivers nothing again.
4. A run of anomalous buckets crossing a poll boundary is delivered without repeating the buckets already delivered; with a minimum run length of 3, two buckets at the end of one poll are delivered together with the third once the next poll completes the run.
5. A failed delivery returns exit code 1 and leaves the watermark unchanged, and the next poll delivers the anomalies; a dry run leaves the watermark unchanged.
6. Realtime polls run when the next bucket has ended plus the ingest delay, unless a fixed polling interval is set; a failed poll is retried after 10, 20, 40… seconds, capped at one bucket; 5 consecutive failures exit with code 1; a poll with too little data resets the failure count.
7. The index and the data stream are written with the anomaly identifier as document id, create-only; HTTP 409 counts as delivered, other errors still fail, and a partial delivery is reported as such.
8. A bucket that ended less than the ingest delay ago is not scored.
