# Build log volume abnormal growth

## Preconditions and setup actions
- RADAR is set up according to [TST-041](./TST.html#TST-041): `radar/.env` filled in, Docker available on the controller host.
- A Linux endpoint reachable from the manager, with `sudo`.

## Test steps

1. On the controller host, the working directory is required to be `radar`:
```
cd radar
```

2. Build RADAR with the `log_volume` scenario (prefix with `sudo` if your user cannot run Docker):
```
./build-radar.sh log_volume
```
This brings up the core stack (indexer, manager, dashboard) and the webhook container, then deploys the scenario's manager-side files, agent group configuration, decoders, rules and lists.

3. Onboard the endpoint (see docs/manual/radar_docs/radar-getting-started.md, *Onboard an endpoint*):
```
sudo ./radar.sh mint-token default,log_volume 60
```
Copy the whole `radar/radar-agent/` folder to the endpoint and, from inside it, run the printed command, e.g.:
```
sudo ./bootstrap-agent.sh --manager <address> --token <token> --group default,log_volume --allow-service <service>
```

4. To clean up the test environment **only after** a _successful_ test execution **AND** a successful execution of [TST-048](./TST.html#TST-048):

- On the controller host: `./stop-radar.sh` (add `--purge` to also remove the volumes).
- On the endpoint, from the `radar-agent` folder: `sudo ./uninstall-agent.sh`.

`--allow-service` is optional: it lists the systemd services `terminate_service.sh` may stop on this endpoint; without it no service can be stopped.

## Expected outcome

### 2. Check the setup

#### In Wazuh Manager

Connect to the Wazuh manager to be able to perform the following verifications:
```
docker exec -it wazuh.manager bash
```
- **2.1** The RADAR snippet for log_volume is present in ossec.conf:
```
grep -A15 'RADAR: log_volume BEGIN' /var/ossec/etc/ossec.conf
```
to ensure the `radar_ar_log_volume` command runs `radar_ar.py` with `<location>server</location>` for `<rules_id>100309</rules_id>`, and `terminate_service.sh` is declared.

- **2.2** The log volume and AD decoders are deployed:
```
ls -l /var/ossec/etc/decoders/0001-log-volume.xml /var/ossec/etc/decoders/0001-ad-common.xml
```
to ensure both files exist.

- **2.3** The log volume rules are deployed:
```
grep -o 'rule id="[0-9]*"' /var/ossec/etc/rules/a1-log-volume.xml
```
to ensure rules 100300 and 100309 are present.

- **2.4** The Filebeat archives pipeline routes the metric to its own index:
```
grep -c 'log_volume_metric' /usr/share/filebeat/module/wazuh/archives/ingest/pipeline.json
```
to ensure the count is at least 1.

- **2.5** The agent group configuration is in place:
```
cat /var/ossec/etc/shared/log_volume/agent.conf
```
to ensure it collects `/var/log/radar/log_volume_metric.log`.

- **2.6** From the controller host, the OpenSearch index template `radar-log-volume` is present:
```
curl -u "$OS_USER:$OS_PASS" -k "$OS_URL/_index_template/radar-log-volume?pretty"
```
to ensure HTTP status 200 and mappings with `data.log_bytes` as `long` and `agent.name` as `keyword`.

- **2.7** Active response files are in place:
```
ls -l /var/ossec/active-response/bin/radar_ar.py /var/ossec/active-response/bin/ar.yaml /var/ossec/active-response/bin/active_responses.env
```
to ensure all three exist.

- **2.8** The agent is registered with the manager:
```
/var/ossec/bin/agent_control -l
```
to ensure an active entry exists for the endpoint (and one for the webhook agent, `ad-webhook`).

- **2.9** Wazuh Manager is running after the deployment:
```
/var/ossec/bin/wazuh-control status
```
to ensure the status output indicates the manager is `running` with no error messages.

#### In endpoints running agents

- **2.10** The Wazuh agent is active and the RADAR active response scripts are installed:
```
systemctl status wazuh-agent
ls -l /var/ossec/active-response/bin/lock_user_linux.sh /var/ossec/active-response/bin/terminate_service.sh
```
to ensure the agent service is active and both scripts exist.

- **2.11** The log volume collector is running:
```
systemctl status radar-log-volume.timer
tail -3 /var/log/radar/log_volume_metric.log
```
to ensure the timer is active and a new `log_volume_metric: /var/log <bytes>` line is appended about every 30 seconds.

#### Post-test cleanup

- **3** Check the cleanup after successful validations, the command output should not list `wazuh.manager`, `wazuh.indexer`, `wazuh.dashboard` or the webhook container:
```
docker ps
```
