# SONAR indexer client: complete, filtered alert reads and one connection

## Preconditions and setup actions

1. SONAR dependencies installed: `poetry install --with sonar,test`.
2. No Wazuh indexer and no network access are needed: the tests replace the OpenSearch client with an in-memory fake that implements point-in-time creation, `search_after` paging and point-in-time deletion, or with mocks.

## Test steps

1. From the repository root, run the indexer client tests:
   ```
   poetry run pytest tests/sonartests/test_indexer_client.py -v
   ```
2. Run the tests of the exclusion of SONAR's own alerts:
   ```
   poetry run pytest tests/sonartests/test_sinks.py -k "OwnAlertsExcluded or rule_group_is_the_one_searches_exclude" -v
   ```

## Expected outcome

1. All 22 tests of step 1 and the 3 selected tests of step 2 pass.
2. **Complete read** (`TestPaginatedSearch`): 25,000 alerts, three per timestamp, are returned all and once each, oldest first, in pages of 10,000; the point-in-time is opened on `wazuh-alerts-*` with a keep-alive of 2 minutes and closed after the search, after an empty result, and when the second page fails, in which case the error is raised.
3. **Query contract**: the query has the `timestamp` range with `gte` start and `lt` end as filter, the alert filter as `must` (no `must` without one), the sort on `timestamp` then `id`, the point-in-time, and counts the matches on the first page only.
4. **Cap**: with `max_alerts` 15,000 and 25,000 matches, 15,000 alerts are returned, the newest alert is among them, the result is oldest first, and the warning names 25,000 and `max_alerts`.
5. **Declared fields** (`TestRequiredSourceFields`): a search with `source_fields` requests exactly those fields and returns no other; the feature builder lists `timestamp`, the numeric, maximum and categorical fields and the derived features' fields; every derived feature declares its fields and gives the same result on an alert reduced to them; the CLI's alert search passes the model's fields and the `alert_filter`.
6. **Own alerts excluded**: by default the query excludes the rule group `sonar` (`must_not`), which is the group of SONAR's Wazuh rules; with `exclude_rule_groups: []` the query has no `must_not`.
7. **One connection** (`TestOneConnection`): `verify_ssl` `false`, `true` and a CA bundle path give the expected TLS arguments; the client gets the URL without trailing slash, basic authentication, the configured timeout and the CA bundle; the alert client and the data stream shipper are both built through the same factory with the CA bundle.
8. **Writes** (`TestIndexAnomaly`, `TestJsonSafe`): an anomaly is created under its `anomaly_id` with NaN written as null; timestamps, numpy numbers, infinity and NaN are converted to JSON values; a 409 conflict counts as delivered while other errors are raised; a dry run sends nothing; the connection check reports a failed ping as `False`.
