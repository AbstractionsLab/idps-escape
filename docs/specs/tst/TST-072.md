# SONAR on RADAR's resource-utilization data

## Preconditions and setup actions

1. SONAR dependencies installed: `poetry install --with sonar,test`.

## Test steps

1. From the repository root, run:
   ```
   poetry run pytest tests/sonartests/test_radar_alignment.py -v
   ```

## Expected outcome

1. The packaged scenario reads `wazuh-archives-*`, requests only `timestamp`, `data.cpu_usage_pct` and `data.mem_usage_pct`, filters on `data.mem_usage_pct` without `radar_seed` documents, uses one-minute buckets with zero fill, and builds the mean and maximum of both metrics from string values.
2. With an agent, the `agent.name` term joins the event filter, the model name and scenario identifier carry the agent, local data is filtered by agent, and a debug run with the `pca` backend trains and detects that agent's model without a feature-settings warning, storing the agent filter in the model.
3. RADAR's detector results are read through every scroll page with a nested `entity` filter for the agent, the scroll is cleared also when a page fails, and the result count is capped.
4. Export fetches the window plus the 119 one-minute buckets of context MVAD needs, writes events, labels and RADAR results that the evaluation reads, exits with 2 when the window is empty, and rejects malformed or out-of-window events and an empty window before connecting.
