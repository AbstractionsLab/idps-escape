# Run RADAR for log volume abnormal growth

## Preconditions and setup actions
- RADAR is built according to the scenario [TST-044](./TST.html#TST-044), and the endpoint's collector has been writing for a few minutes, so that `wazuh-ad-log-volume-*` holds documents.

## Test steps
1. The working directory is required to be `radar`:
```
cd radar
```
2. Run RADAR with SCENARIO_NAME log_volume. Add `--ingest true` to seed a synthetic history for the agent named in `scenarios.log_volume.ingest.agent_name` of `config.yaml`, so that the detector has a baseline at once:
```
./run-radar.sh log_volume
```

## Expected outcome
2. The command prints the detector ID and the monitor ID. In the Wazuh Dashboard:

    2.1. In the Anomaly Detection menu, the detector `LOG_VOLUME_DETECTOR` is listed, started, with the configuration of `log_volume` in [`config.yaml`](/radar/config.yaml): index `wazuh-ad-log-volume-*`, feature `log_volume_max`, category field `agent.name`, interval 1 minute.

    2.2. In the Alerting menu, the monitor `LogVolume-Monitor` is listed under Monitors, enabled, with the trigger `LogVolume-Growth-Detected` and an action to the `RADAR Webhook` notification channel.

    2.3. Running the command a second time creates no second detector or monitor.
