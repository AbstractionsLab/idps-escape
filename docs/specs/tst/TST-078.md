# RADAR: off-hours rule mode end to end

## Preconditions and setup actions

- Same generic preconditions as [TST-055](./TST.html#TST-055).
- `suspicious_login` deployed with `./radar.sh run suspicious_login`, the webhook running, and an agent bootstrapped with the `suspicious_login` group.
- For step 2, a test account on the agent listed in `scenarios.suspicious_login.off_hours.users` under a rule-mode group whose hours exclude the current time, deployed again after the change, and with no off-hours event in the last `quiet_minutes`.

**Test data**: test users test_off_user and test_on_user, the reference event for bob (2026-09-18T02:05:00Z), and an SSH login of a listed user

## Test steps

1. From `radar/`, run `poetry run python radar-test-framework/checks/off_hours_rule_e2e.py --env .env`.
2. Log in to the agent over SSH as the test account. After `delay_minutes` plus up to one `interval_minutes`, run `off_hours.py status --mode rule` (see the manual, *Off-hours activity*).
3. Log in again within `quiet_minutes` and wait one more interval.
4. Run `docker exec wazuh.manager grep '"id":"210041"' /var/ossec/logs/alerts/alerts.json | tail -2` on the manager host and inspect `/var/ossec/logs/active-responses.log`.

## Expected outcome

1. The script prints `PASS` for:
   - one report for `test_off_user` with count 1 and group `test_always_off`;
   - none for `test_on_user`, whose event is flagged 0;
   - no second report one interval later;
   - a new report after the quiet period;
   - `bob` reported with count 1 and first event at 02:05;
   - an inline run of the monitor that fires and renders a webhook item with user, count and group.

   It ends with `[ok]` and removes its temporary index and pipeline.
2. `status` shows one monitor alert, then one webhook line for the account whose decoded data has `off_hours_count` and `schedule_group`, matched by rule 210041.
3. No second webhook line or 210041 alert for the account.
4. One 210041 alert for the account; `radar_ar.py` decides it as `suspicious_login` with detection `ad`.

## Cleanup

1. Remove the test account from `scenarios.suspicious_login.off_hours.users` and redeploy.
