# Build scanning detection

## Preconditions and setup actions
- RADAR is set up according to [TST-041](./TST.html#TST-041): `radar/.env` filled in, Docker available on the controller host.
- A Linux endpoint reachable from the manager, with `sudo`.

## Test steps

1. On the controller host, the working directory is required to be `radar`:
```
cd radar
```

2. Build RADAR with the `scanning_detection` scenario (prefix with `sudo` if your user cannot run Docker):
```
./build-radar.sh scanning_detection
```
This brings up the core stack (indexer, manager, dashboard) and the webhook container, then deploys the scenario's manager-side files, agent group configuration, decoders, rules and lists.

3. Onboard the endpoint (see docs/manual/radar_docs/radar-getting-started.md, *Onboard an endpoint*):
```
sudo ./radar.sh mint-token default,scanning_detection 60
```
Copy the whole `radar/radar-agent/` folder to the endpoint and, from inside it, run the printed command, e.g.:
```
sudo ./bootstrap-agent.sh --manager <address> --token <token> --group default,scanning_detection
```

4. To clean up the test environment **only after** a _successful_ test execution **AND** a successful execution of [TST-052](./TST.html#TST-052):

- On the controller host: `./stop-radar.sh` (add `--purge` to also remove the volumes).
- On the endpoint, from the `radar-agent` folder: `sudo ./uninstall-agent.sh`.
## Expected outcome

### 2. Check the setup

#### In Wazuh Manager

Connect to the Wazuh manager to be able to perform the following verifications:
```
docker exec -it wazuh.manager bash
```
- **2.1** The scanning detection rules are deployed:
```
grep -o 'rule id="[0-9]*"' /var/ossec/etc/rules/a4-scanning-detection.xml
```
to ensure rules 100810, 100815, 100820, 100821, 100825, 100826, 100827, 100828, 100829, 100830, 100831, 100832, 100835 and 100840 are present.

- **2.2** The scenario's lists are deployed and declared:
```
ls -l /var/ossec/etc/lists/radar_scanning_allowlist /var/ossec/etc/lists/radar_webdav_apps
grep -n 'radar_scanning_allowlist\|radar_webdav_apps' /var/ossec/etc/ossec.conf
```
to ensure both lists exist and are declared under `<ruleset>`.

- **2.3** Only the confirmation rule is bound to the RADAR active response:
```
grep -A15 'RADAR: scanning_detection BEGIN' /var/ossec/etc/ossec.conf
```
to ensure the `radar_ar_scanning` command runs `radar_ar.py` with `<location>server</location>` for `<rules_id>100830</rules_id>` only.

- **2.4** The agent group configuration is in place:
```
cat /var/ossec/etc/shared/scanning_detection/agent.conf
```
to ensure it collects `/var/log/suricata/eve.json` as `json` and the Apache and Nginx access logs as `apache`.

- **2.5** Active response files are in place:
```
ls -l /var/ossec/active-response/bin/radar_ar.py /var/ossec/active-response/bin/ar.yaml /var/ossec/active-response/bin/active_responses.env
```
to ensure all three exist.

- **2.6** The agent is registered with the manager:
```
/var/ossec/bin/agent_control -l
```
to ensure an active entry exists for the endpoint (and one for the webhook agent, `ad-webhook`).

- **2.7** Wazuh Manager is running after the deployment:
```
/var/ossec/bin/wazuh-control status
```
to ensure the status output indicates the manager is `running` with no error messages.

#### In endpoints running agents

- **2.8** The Wazuh agent is active and the RADAR active response scripts are installed:
```
systemctl status wazuh-agent
ls -l /var/ossec/active-response/bin/lock_user_linux.sh /var/ossec/active-response/bin/terminate_service.sh
```
to ensure the agent service is active and both scripts exist.

- **2.9** Suricata is running and writes HTTP events:
```
systemctl status suricata
tail -5 /var/log/suricata/eve.json | grep '"event_type":"http"'
```
to ensure Suricata is active and `eve.json` contains recent `http` events (with `http.status`, `http.http_method` and `http.http_user_agent`) for the web server's traffic.

#### Post-test cleanup

- **3** Check the cleanup after successful validations, the command output should not list `wazuh.manager`, `wazuh.indexer`, `wazuh.dashboard` or the webhook container:
```
docker ps
```
