# Validate default scenario rules deployment

## Preconditions and setup actions
- RADAR is set up according to [TST-041](./TST.html#TST-041): `radar/.env` filled in, Docker available on the controller host.
- A Linux endpoint reachable from the manager, with `sudo`.

## Test steps

1. On the controller host, the working directory is required to be `radar`:
```
cd radar
```

2. Build RADAR with any scenario; the `default` rules and response binding are deployed with every scenario. For example, the `suspicious_login` scenario (prefix with `sudo` if your user cannot run Docker):
```
./build-radar.sh suspicious_login
```
This brings up the core stack (indexer, manager, dashboard) and the webhook container, then deploys the scenario's manager-side files, agent group configuration, decoders, rules and lists.

3. Onboard the endpoint (see docs/manual/radar_docs/radar-getting-started.md, *Onboard an endpoint*):
```
sudo ./radar.sh mint-token default,suspicious_login,radar_shared 60
```
Copy the whole `radar/radar-agent/` folder to the endpoint and, from inside it, run the printed command, e.g.:
```
sudo ./bootstrap-agent.sh --manager <address> --token <token> --group default,suspicious_login,radar_shared
```

4. To clean up the test environment **only after** a _successful_ test execution **AND** a successful execution of [TST-054](./TST.html#TST-054):

- On the controller host: `./stop-radar.sh` (add `--purge` to also remove the volumes).
- On the endpoint, from the `radar-agent` folder: `sudo ./uninstall-agent.sh`.

## Expected outcome

#### In Wazuh Manager

Connect to the Wazuh manager:
```
docker exec -it wazuh.manager bash
```

- **2.1** The RADAR rules of the default scenario are deployed:
```
grep -o 'rule id="[0-9]*"' /var/ossec/etc/rules/radar_rules.xml
```
to ensure rule IDs 100400 to 100405 are present.

- **2.2** `ar.yaml` maps the default scenario:
```
grep -A12 "^  default:" /var/ossec/active-response/bin/ar.yaml
```
to ensure `signature.rule_ids` lists 100401, 100402, 100404, 100405, 23503, 23504, 23505 and `rule_groups` lists `authentication_failures`.

- **2.3** The active-response binding in `ossec.conf` includes both the exact IDs and the group:
```
grep -A12 'radar_ar_default' /var/ossec/etc/ossec.conf
```
to ensure one `<active-response>` lists `<rules_id>100401,100402,100404,100405,23503,23504,23505</rules_id>` and another `<rules_group>authentication_failures,</rules_group>`, both with `<location>server</location>`.

- **2.4** Wazuh Manager is running after the deployment:
```
/var/ossec/bin/wazuh-control status
```
to ensure status output indicates `running` with no error messages.

#### Post-test cleanup

- **3** Check the cleanup after successful validations, the command output should not list `wazuh.manager`, `wazuh.indexer`, `wazuh.dashboard` or the webhook container:
```
docker ps
```
