# GUI: Build and deploy `linux_resource_utilization`

This test checks that the `linux_resource_utilization` scenario can be deployed on the manager, that a Linux agent can be onboarded into it, that the agent's CPU and memory metrics reach OpenSearch, and that everything can be removed again.

## Preconditions and setup actions
- Same generic preconditions as [TST-055](./TST.html#TST-055). No MaxMind key is needed for this scenario.
- The `linux_resource_utilization` scenario is not deployed on the manager, and the agent host has no Wazuh agent installed.

## Test steps

1. On the controller host, prepare `.env`:
```bash
cd radar
cp env.example .env
```
Edit it with the values described in the preconditions of [TST-055](./TST.html#TST-055).

2. Start the GUI:

```bash
./radar.sh gui
```
Open the login URL printed in the terminal (`http://127.0.0.1:5000/?token=…`). If the browser runs on another machine, first open an SSH tunnel to the controller: `ssh -L 5000:127.0.0.1:5000 <user>@<controller>`.

3. In the GUI, go to **Deployment → Scenario Management → Deploy scenario**, select scenario `Linux Resource Utilization`, and click **Deploy**. If prompted for the sudo password, enter it.

4. In the GUI, go to **Deployment → Agent Management → Onboard agent**. Select scenario `Linux Resource Utilization`, click **Mint token**, and copy the printed `bootstrap-agent.sh` command.

5. Copy the whole `radar-agent` folder to the agent host:
```bash
scp -r radar-agent <user>@<agent-host>:~/
ssh <user>@<agent-host>
cd radar-agent
```
Then, on the agent host and from inside that folder, run the command copied in step 4, exactly as printed or with an added `--agent-name` argument.

6. In the GUI, go to **Deployment → Group Management**. Enter the agent's IP/name, select scenario `Linux Resource Utilization`, and click **Assign group**. **Optional, this step is only required if bootstrap is run not the first time.**

7. On the agent host, check the metric collector:
```bash
systemctl list-timers | grep radar-linux-resource-utilization
tail -n 3 /var/log/radar/resource_usage_metric.log
```

8. In the GUI, go to **Deployment → Anomaly Detector → Run Anomaly Detector**, choose `Linux Resource Utilization`, **check** the ingest option box, and press **Run**.

9. On the controller, count the agent's metric events in OpenSearch (replace `<agent-name>`):
```bash
(set -a; source .env; set +a; curl -s -k -u "$OS_USER:$OS_PASS" "$OS_URL/wazuh-archives-*/_count?q=agent.name:<agent-name>+AND+_exists_:data.mem_usage_pct&pretty")
```

10. Check the health of the manager: in **Deployment → Status**, choose the `Linux Resource Utilization` scenario and press **Run health check**.

11. Run the steps in Cleanup.

## Cleanup

1. In the GUI, bring down and remove the Wazuh stack from **Deployment → Teardown**.

2. Uninstall the agent from its host with:

```bash
ssh <user>@<agent-host>
cd radar-agent    # the folder copied for bootstrap-agent.sh
sudo ./uninstall-agent.sh --purge-data
```

Afterwards, verify that:

- `systemctl list-timers | grep radar-linux-resource-utilization` prints nothing
- `/usr/local/bin/radar-linux-resource-utilization-metric.sh` no longer exists
- `dpkg -l wazuh-agent` reports nothing.

## Expected outcome

1. `.env` exists on the controller with the required variables set.

2. The GUI is reachable in a browser, and the **Deployment** page shows the **Scenario Management**, **Agent Management**, **Group Management**, and **Anomaly Detector** tabs.

3. `Linux Resource Utilization` is listed in the scenario dropbox lists and is indicated as "not deployed". The streamed output completes with `=== SUCCESS` and no `[ERROR]` line.

4. A ready-to-run command of the form `sudo ./bootstrap-agent.sh --manager <address> --token <token> --group default,linux_resource_utilization` is printed.

5. The command completes with `=== SUCCESS ===`, and its output contains `OK - installed and started radar-linux-resource-utilization.timer`.
On the Wazuh Dashboard, **Agents management → Summary** shows the agent in group `linux_resource_utilization`.

6. On the Wazuh Dashboard, **Agents management → Summary** shows the agent in group `linux_resource_utilization`.

7. The timer `radar-linux-resource-utilization.timer` is listed, and the log shows lines of the form `<timestamp> <hostname> resource_usage_metric: cpu=<cpu_pct> mem=<mem_pct>`, about 30 seconds apart.

8. The streamed output shows `Done` and contains the messages `[+] Created detector 'LINUX_RESOURCE_UTILIZATION_DETECTOR'` and `[✓] Started detector`. The "Output" screen does not show any errors.

9. `count` is greater than `0`.

10. No `FAIL` line is present, and all checks report `OK`.

11. The cleanup completes as described in Cleanup.
