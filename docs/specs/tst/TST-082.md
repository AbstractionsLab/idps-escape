# RADAR agent onboarding and enrollment hardening

## Preconditions and setup actions

- Automated part (steps 1 and 2): a repository checkout with `poetry install --with radar,test`, plus `bats`, `jq` and, optionally, `shellcheck` on the `PATH`. No RADAR stack, network or Docker is needed. Alternatively, `radar/test.sh` runs the whole RADAR suite in the `radar/Dockerfile.test` image, which provides these tools.
- Manual part (steps 3 to 12):
  - A RADAR host with `radar/.env`, root through `sudo`, and `log_volume` deployed with `sudo ./build-radar.sh log_volume`.
  - Endpoint A and endpoint B: clean, supported Debian or Ubuntu hosts that can reach the RADAR host and `packages.wazuh.com`. A copy of `radar/radar-agent/` on each, in `~/radar-agent`.
  - `MGR` is the RADAR host address printed by `radar.sh mint-token`. Commands marked *(host)* run in `radar/` on the RADAR host, *(A)* and *(B)* in `~/radar-agent` on the endpoints.

## Test steps

1. From `radar/`, run:
   ```
   PYTHONPATH=anomaly_detector:. poetry run pytest tests/py/test_token_revocation.py tests/py/test_radar_agent_mapping.py tests/py/test_radar_agent_collectors.py -v
   ```
2. From `radar/`, run:
   ```
   for s in bootstrap-agent uninstall-agent ar-mapping ar-dispatch collectors; do bats -p tests/bash/$s.bats; done
   ```
3. **Hardened manager** *(host)*: `docker exec wazuh.manager grep -E '<use_password>|<purge>' /var/ossec/etc/ossec.conf`; compare the `<key>` of the `<cluster>` block with `WAZUH_CLUSTER_KEY` in `.env`; `sudo ./radar.sh enrollment status`. *(A)*: `timeout 5 bash -c "</dev/tcp/$MGR/1515"; echo $?`.
4. **Window auto-close** *(host)*: `sudo ./radar.sh enrollment open --minutes 1`, `sudo ./radar.sh enrollment status`; *(A)*: repeat the port probe. Wait two minutes; *(host)* status again; *(A)* probe again.
5. **Invalid token, incomplete folder, unreachable manager** *(host)*: `sudo ./radar.sh enrollment open --minutes 30`. *(B)*: `sudo ./bootstrap-agent.sh --manager $MGR --token wrong --group default`; then copy the folder to `~/broken`, delete `~/broken/helpers/collectors.sh`, and run `sudo ~/broken/bootstrap-agent.sh --manager $MGR --token wrong --group default`; then `time sudo ./bootstrap-agent.sh --manager 198.51.100.1 --token wrong --group default`.
6. **No credential** *(B)*: `sudo /var/ossec/bin/agent-auth -m $MGR -A b-nopass` (no `-P`).
7. **Onboarding** *(host)*: `sudo ./radar.sh mint-token default,log_volume 30`. *(A)*: run the printed `bootstrap-agent.sh` command, adding `--agent-name endpoint-a`. Then *(A)*: `ls -l /var/ossec/active-response/bin/ /var/ossec/radar-agent/`, `apt-mark showhold`, `systemctl is-active wazuh-agent radar-log-volume.timer`. *(host)*: `./health-radar.sh --scenario log_volume --agent-name endpoint-a` and `docker exec wazuh.manager /var/ossec/bin/manage_agents -l`.
8. **Duplicate name** *(B)*: with the token of step 7, `sudo /var/ossec/bin/agent-auth -m $MGR -P <token> -A endpoint-a`; *(host)*: `manage_agents -l` again.
9. **Re-run** *(host)*: mint a new token as in step 7. *(A)*: run the new bootstrap command again with `--agent-name endpoint-a`; *(host)*: `manage_agents -l`.
10. **Superseded and expired tokens** *(B)*: `sudo /var/ossec/bin/agent-auth -m $MGR -P <token of step 7> -A b-old`. *(host)*: `sudo ./radar.sh mint-token default 1`, wait two minutes, `sudo journalctl -u radar-token-revoke.service -n 5`, `ls .radar-state/`, then reopen the window with `sudo ./radar.sh enrollment open --minutes 10` so that a refusal cannot come from the firewall. *(B)*: `sudo /var/ossec/bin/agent-auth -m $MGR -P <1-minute token> -A b-expired`.
11. **Uninstall and reinstall** *(A)*: `sudo ./uninstall-agent.sh`; `dpkg -l wazuh-agent`, `ls -l /var/lib/radar-agent`, `systemctl status wazuh-agent`. *(host)*: mint a token. *(A)*: bootstrap again with `--agent-name endpoint-a`; *(host)*: `manage_agents -l`.
12. **Purge** *(A)*: `sudo ./uninstall-agent.sh --purge-data`; `ls /var/ossec /var/lib/radar-agent /var/log/radar`. *(host)*: `./radar_deploy/manager-deregister-agent.sh --agent-name endpoint-a`, and the same for any agent created on B.

## Expected outcome

1. All tests pass. In particular: a bad token lifetime (`0`, `99999`, `1;id`, ...) is refused before any `docker` call; an unexpired token is left alone and an expired one is replaced and the manager restarted; the shell and Python catalog parsers agree on the shipped catalog; every catalog name is an action `radar_ar.py` can target and every script is shipped; collectors are named after real scenarios and their units and log rotation are consistent.
2. All tests pass (the `shellcheck` tests are informational). In particular: required options, root and folder completeness are checked before any change; every catalog script gets a dispatcher and a root-owned copy in the agent home; one `agent-auth` call carries manager, token, name and all groups; "Duplicate agent name" is success only with a local key; an invalid password fails with a token and reachability hint; the agent is held; a kept key is restored only for the same name and manager; the dispatcher refuses unmapped names, broken catalogs and group- or world-writable or foreign-owned files; collectors are validated, installed idempotently and removed exactly; uninstall keeps the key unless `--purge-data`.
3. `<use_password>yes</use_password>` and `<purge>no</purge>`; the cluster key equals `WAZUH_CLUSTER_KEY`; status `CLOSED - port 1515 is blocked`; the probe fails (non-zero).
4. After opening: status `OPEN` with a timer PID, probe succeeds (0). After two minutes: status `CLOSED`, probe fails.
5. The invalid token fails with `FAILED: enrollment rejected by manager` and a next step about the token and port 1515 (the package is installed by this run). The incomplete folder fails with `FAILED: ... helpers is incomplete` before any change. The unreachable manager fails with a non-zero status within the `agent-auth` connection timeout, without a key being written.
6. Refused; no key is issued and no agent `b-nopass` appears on the manager.
7. The mint prints the bootstrap command and opens the window. The bootstrap ends with `=== SUCCESS ===`. Dispatchers `lock_user_linux.sh` and `terminate_service.sh` are present (`root:wazuh`, 0750); `/var/ossec/radar-agent` holds the catalog and every script; `wazuh-agent` is held; both units are `active`. The health check shows `endpoint-a` active and in groups `default` and `log_volume`; `manage_agents -l` lists it once.
8. `agent-auth` reports "Duplicate agent name"; `endpoint-a` keeps its ID and is listed once.
9. The bootstrap ends with `=== SUCCESS ===` after reporting that the name is already registered with a local key; `endpoint-a` is still listed once with the same ID.
10. The superseded token is refused. After the 1-minute token's lifetime, the journal of `radar-token-revoke.service` shows `OK - enrollment token revoked on wazuh.manager`, `enrollment-token.expires` is gone, and the expired token is refused.
11. The package is removed, the service is no longer registered, and `/var/lib/radar-agent` holds the key (root-only). The reinstall reconnects as the same agent: same ID, groups unchanged, listed once.
12. `/var/ossec`, `/var/lib/radar-agent` and `/var/log/radar` no longer exist. Deregistration reports success.

The test passes when every expected outcome is observed.
