# Linux resource usage monitoring scenario

## Preconditions and setup actions

1. SONAR dependencies installed: `poetry install --with adbox,radar,test`.
2. `sonar/scenarios/linux_resource_monitoring.yaml` is present with `debug.enabled: false` (the `--debug` CLI flag is used instead).
3. The following local test data files exist:
   - `sonar/test_data/resource_monitoring/resource_monitoring_training-2.json`
   - `sonar/test_data/resource_monitoring/resource_monitoring_detection.json`

## Test steps

1. From the repository root, train the SONAR model for the Linux resource monitoring scenario using local debug data:
   ```
   poetry run sonar train --scenario sonar/scenarios/linux_resource_monitoring.yaml --debug
   ```

2. Verify the training log reports successful completion and a model artefact is persisted under `sonar/models/` with the name matching the `model_name` field in the scenario YAML (`linux_resource_monitoring_20260112_230114`).

3. From the repository root, run anomaly detection for the Linux resource monitoring scenario using the local debug detection data:
   ```
   poetry run sonar detect --scenario sonar/scenarios/linux_resource_monitoring.yaml --debug
   ```

4. Inspect the detection output log and verify that at least one anomaly is flagged with a score exceeding the configured threshold (`0.75`).

5. Verify that at least `min_consecutive: 3` consecutive anomalous 1-minute buckets are present in the reported output, satisfying the sustained-anomaly criterion.

6. Verify in the detection log that derived features reflect the expected Boolean classifications: buckets with `cpu_usage_% ≥ 80` carry `is_cpu_high = True`; buckets with `memory_usage_% ≥ 80` carry `is_memory_high = True`; buckets with `1min_loadAverage ≥ 4.0` carry `is_high_load = True`.

## Expected outcome

1. Training completes without error; a model file named `linux_resource_monitoring_20260112_230114` is persisted to disk.
2. Detection completes without error.
3. At least one anomaly is flagged; the anomaly score for each reported bucket exceeds `0.75`.
4. At least three consecutive anomalous 1-minute buckets appear in the flagged output.
5. Derived features `is_cpu_high`, `is_memory_high`, and `is_high_load` carry Boolean values consistent with the raw metric thresholds applied to the detection data.
