# SONAR paths, detector backends, model files and package

## Preconditions and setup actions

1. SONAR dependencies installed: `poetry install --with sonar,test`.
2. Poetry available on the path, to build the wheel.

## Test steps

1. From the repository root, run:
   ```
   poetry run pytest tests/sonartests/test_paths.py tests/sonartests/test_backends.py tests/sonartests/test_packaging.py -v
   ```

## Expected outcome

1. `$SONAR_HOME` decides the default locations when set; otherwise the package directory of a source checkout, otherwise `~/.sonar`. Paths in a configuration or scenario file resolve against that file; the resolved model, data and state locations are identical from three different working directories; the default and packaged scenarios point at the packaged debug data; a scenario without `model_name` uses its name; the default scenario ID is the model name.
2. No module of the `sonar` package outside its test-data scripts contains a `./` path literal or calls `getcwd`/`cwd`.
3. Every backend (`mvad`, `pca`, `ewma`) gives one verdict per bucket after its context and normalised results (severity in [0, 1], 0 for non-anomalies, contributors in decreasing order), finds the injected alert burst, and gives the same verdicts after saving and loading; the model directory holds `metadata.json` with the backend name and columns, no pickle, and no leftover staging directory.
4. The `ewma` backend validates its parameters, refuses too little training data, and maps the threshold to severity 0.5 and twice the threshold to 1; an unknown backend, a missing model and an unknown model format version are refused.
5. The `pca` backend validates its parameters and refuses too little training data; it finds both injected anomalies with the injected feature as top contributor, flags at most 5 % of the normal buckets, flags a bucket whose two features are each in their usual range but break their training correlation, scores the first change of a feature that never moved in training as anomalous with a finite score, and takes its settings from the configuration file and, overriding them, from the scenario.
6. The `mvad` backend reproduces the timestamps, verdicts, severities and scores recorded in `tests/assets/sonar_mvad_regression.json` before the backend interface existed, and its weights load as plain tensors with `weights_only=True`.
7. The built wheel contains the example scenarios, their debug datasets, the default configuration and the Wazuh rules, and nothing from `adbox/assets/secrets/`, `sonar/models/` or `.env` files; its `sonar` package, run from a temporary directory with `SONAR_HOME` set, trains and detects on the packaged `linux_resource_monitoring` scenario in debug mode and writes SONAR events to the `jsonl` sink, without touching the repository.
