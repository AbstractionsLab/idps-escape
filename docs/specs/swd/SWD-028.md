# RADAR detector module design

This document specifies the software design of `radar/anomaly_detector/detector.py`, which creates and starts the OpenSearch Anomaly Detection (RCF) detector of a RADAR scenario from its `config.yaml` block. It is used for `log_volume` and `linux_resource_utilization`; the `suspicious_login` model-mode detector is built by `radar/anomaly_detector/off_hours.py`, which reuses this module's specification builder, detector lookup and session helpers.

## Module overview

The module is a script of plain functions (no classes) that:

1. finds an existing detector by name (idempotent),
2. builds the detector specification from the scenario block,
3. waits until the source index has documents, then creates the detector,
4. starts the detector (new or existing) and prints its ID.

## Function specifications

Signatures as implemented (bodies omitted). `sess` is a `requests.Session` with basic auth; `base` the indexer URL.

```python
def find_detector_id(sess, base: str, name: str, verify: bool, timeout: float) -> str | None:
    """POST /_plugins/_anomaly_detection/detectors/_search, exact name.keyword match.
    A 404 (AD system index not created yet) means no detector."""

def detector_spec(scn_name: str, scn: dict) -> dict:
    """AD detector body named f"{scn_name.upper()}_DETECTOR"."""

def wait_for_documents(sess, base: str, index_pattern: str, verify: bool, timeout: float,
                       attempts: int = 10, delay_seconds: float = 1.0) -> None:
    """Poll <index_pattern>/_count until it is non-zero or attempts run out."""

def create_detector(sess, base: str, spec: dict, verify: bool, timeout: float) -> str:
    """wait_for_documents, then POST /_plugins/_anomaly_detection/detectors; returns _id."""

def start_detector(sess, base: str, det_id: str, verify: bool, timeout: float) -> None:
    """POST /_plugins/_anomaly_detection/detectors/{det_id}/_start."""
```

Helpers: `index_pattern(scn)`, `build_features(scn)`, `build_filter_query(scn)`, `build_category_field(scn)`, `build_rules(scn)`, `pick_scenario(cfg, name)`, `load_env(path)`, `make_session(user, pwd)`.

## Main orchestration

`main()`, run as `python detector.py <scenario>` from the directory holding `config.yaml` and `.env`:

1. Load `.env` (values already in the environment win) and `config.yaml`.
2. Select the scenario block; an unknown scenario exits with an error.
3. Find the detector `<SCENARIO>_DETECTOR`; if absent, build the specification and create it.
4. Start the detector.
5. Write the detector ID to stdout; progress messages go to stderr.

**Environment variables:** `OS_URL` (required), `OS_USER`, `OS_PASS`, `OS_VERIFY_SSL` (default true), `OS_TIMEOUT` (seconds, default 30).

**Exit codes:** 0 (success), 1 (any error, message on stderr).

## Configuration schema

Scenario keys read by `detector_spec()`:

| Key | Required | Default | Detector field |
|---|---|---|---|
| `log_index_pattern` or `index_prefix` | yes | — | `indices` (`log_index_pattern`, else `<index_prefix>-*`) |
| `time_field` | yes | — | `time_field` |
| `result_index` | yes | — | `result_index` |
| `features` | yes | — | `feature_attributes` |
| `detector_interval` | no | 5 | `detection_interval` (minutes) |
| `delay_minutes` | no | 1 | `window_delay` (minutes) |
| `shingle_size` | no | 8 | `shingle_size` |
| `categorical_field` | no | none | `category_field` |
| `filter_query` | no | match all | `filter_query` (must be a mapping) |
| `imputation_option` | no | `{method: ZERO}` | `imputation_option` |
| `rules` | no | none | `rules` (e.g. `IGNORE_ANOMALY` conditions) |
| `result_index_min_age`, `result_index_min_size`, `result_index_ttl`, `flatten_custom_result_index` | no | 10, 51200, 60, false | result index settings |

See [radar/config.yaml](../../../radar/config.yaml) for the shipped scenarios.

## Error handling

- **Detector already exists**: reused and started again; it is not compared with or updated to the current configuration.
- **Empty source index**: creation waits up to `attempts × delay_seconds` for documents, then tries anyway; the AD plugin may then refuse to start it.
- **API errors**: a non-201 create or non-200 start response, or any HTTP or other exception, prints the status and body on stderr and exits 1. There is no retry.

## Integration

`run-radar.sh <scenario>` runs the module in the `radar-cli` container and passes the printed ID to `monitor.py` (SWD-029).
