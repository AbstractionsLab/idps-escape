# SONAR class structure and relationships

## Class diagram overview

The SONAR subsystem employs a modular class structure organized around configuration management, data access, and processing pipelines.

### Core configuration classes

```plantuml
@startuml
class PipelineConfig {
  +WazuhIndexerConfig wazuh
  +MVADConfig mvad
  +FeatureConfig features
  +DebugConfig debug
  +ShippingConfig shipping
  +str model_path
}

class WazuhIndexerConfig {
  +str base_url
  +str username
  +str password
  +bool verify_ssl
  +str alerts_index_pattern
}

class MVADConfig {
  +int sliding_window
  +str device
  +Dict extra_params
  +to_params() Dict
}

class FeatureConfig {
  +Sequence<str> numeric_fields
  +int bucket_minutes
  +int categorical_top_k
  +bool derived_features
}

PipelineConfig *-- WazuhIndexerConfig
PipelineConfig *-- MVADConfig
PipelineConfig *-- FeatureConfig
@enduml
```

### Scenario management classes

```plantuml
@startuml
class UseCase {
  +str name
  +str description
  +Optional<str> model_name
  +TrainingScenario training
  +DetectionScenario detection
  +from_yaml(path) UseCase
  +to_yaml(path) void
}

class TrainingScenario {
  +int lookback_hours
  +List<str> numeric_fields
  +int bucket_minutes
  +int sliding_window
}

class DetectionScenario {
  +str mode
  +int lookback_minutes
  +float threshold
  +int min_consecutive
}

UseCase *-- TrainingScenario
UseCase *-- DetectionScenario
@enduml
```

## Design patterns

| Pattern | Application | Benefit |
|---------|-------------|---------|
| **Dataclasses** | Configuration objects | Type safety, immutability, validation |
| **Factory Method** | `UseCase.from_yaml()` | Encapsulates YAML parsing logic |
| **Strategy** | Data providers (Wazuh/Local) | Interchangeable data sources |
| **Facade** | Engine wrapper | Simplifies MVAD library interface |
