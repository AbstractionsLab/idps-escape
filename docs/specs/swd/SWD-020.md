# RATF: simulation phase

## Sequence diagram of threat simulation in RATF

The simulation phase is the part of the RADAR Automated Test Framework that is implemented (`radar/radar-test-framework/simulate/scenarios/`, designed in SWD-039). The operator copies a scenario's script to an enrolled endpoint and runs it there:

1. The script writes the scenario's artefact on the endpoint: authentication log lines, web access-log lines, Suricata `eve.json` records, filesystem growth, or real CPU and memory load.
2. The endpoint's Wazuh agent ships the resulting log lines or collector metrics to the manager, like any other event. The simulator never writes to the indexer.
3. Signature scenarios: the manager's decoders, enrichment and rules raise the alert. Anomaly scenarios: the events are indexed, the detector reports an anomaly, the monitor posts it to the webhook, and the webhook's agent sends the `ad_alert` line that the manager's AD rules match.
4. The matching rule triggers `radar_ar.py`, which scores the alert, sends the notification and FlowIntel case, and, when the tier and `allow_mitigation` allow it, triggers containment active responses on the endpoint.
5. The operator checks the result against the rule IDs the script printed for each case.

For fusion tests of `suspicious_login`, `inject_ad_alert.py` runs on the RADAR host instead and posts an anomaly alert directly to the webhook, replacing steps 1 to 3 for the anomaly side.

```mermaid
%% radar/radar-test-framework/simulate/scenarios/
sequenceDiagram
  actor Op as Operator
  participant SIM as Simulate script (endpoint)
  participant AG as Wazuh agent (endpoint)
  participant MGR as Wazuh manager
  participant IDX as Wazuh indexer
  participant WH as ad-webhook and its agent
  participant AR as radar_ar.py
  Op->>SIM: copy the scenario's script to the endpoint and run it
  SIM->>SIM: write artefact to local logs, files or CPU and memory load
  SIM-->>Op: expected rule IDs per case
  Note over SIM,IDX: The simulator never writes to the indexer
  AG->>MGR: ship log lines or collector metrics
  alt signature scenario
    MGR->>MGR: decoders, enrichment and rules raise the alert
  else anomaly scenario
    MGR->>IDX: index archived events
    IDX->>IDX: detector reports an anomaly
    IDX->>WH: monitor posts the anomaly
    WH->>MGR: ad_alert line
    MGR->>MGR: AD rules match
  end
  Note over IDX,WH: suspicious_login fusion tests: inject_ad_alert.py on the RADAR host posts the anomaly to the webhook directly
  MGR->>AR: matching rule triggers radar_ar.py
  AR->>AR: score the alert, send notification and FlowIntel case
  opt tier and allow_mitigation allow it
    AR->>AG: containment active response (via Wazuh API)
  end
  Op->>MGR: check the result against the printed rule IDs
```
