# SONAR feature contract between training and detection

SONAR SHALL record in every persisted model the feature configuration, the categorical vocabulary (the category values that have their own feature) and the feature layout version it was trained with. Detection SHALL build its features from the model's recorded configuration and vocabulary, SHALL count category values unseen in training in a dedicated "other" feature, and SHALL refuse to predict on features that differ from the training features or to load a model with a different feature layout version.

### Rationale

Recomputing the category vocabulary from each detection window, and silently zero-filling or dropping columns that differ, discarded exactly the new categories that indicate an attack and applied models to data they were not trained on without any warning.

### Acceptance criteria

1. A category value unseen in training is counted in the "other" feature at detection, and the detection features equal the training features.
2. When the scenario's feature settings differ from the model's, detection warns and uses the model's settings.
3. Predicting on features that differ from the training features fails with an error naming the differing features.
4. Loading a model with a different or unknown feature layout version fails with a request to retrain.
