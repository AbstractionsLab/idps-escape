# Centralized C&C Deployment

As a system admin user,
I want to deploy and maintain a central subsystem, called command-and-control (C&C),
so that I can update user-exposed settings of subsystems tackling data collection, intrusion detection and prevention.

1. Set up a GNU/Linux host with Docker for the C&C server.
2. Access as root.
3. Deploy C&C components following:

  ```mermaid
  flowchart TB
    S(["Deploy IDPS-ESCAPE C&C server"]) --> W["Deploy CyFORT-Wazuh:<br/>build-radar.sh --core-only"]
    W --> N{"NIDS?"}
    N -->|yes| SUR["Deploy C-CyFORT-Suricata"]
    N -->|no| AD
    SUR --> AD{"Anomaly detection?"}
    AD -->|yes| SON["Deploy SONAR<br/>(ADBox v1 for existing deployments)"]
    AD -->|no| RS
    SON --> RS{"RADAR scenarios?"}
    RS -->|yes| BR["build-radar.sh #lt;scenario#gt;"]
    RS -->|no| EP
    BR --> EP{"Add end-point?"}
    EP -->|yes| MOD["Select end-point model"]
    MOD --> TOK["Mint token, run<br/>bootstrap-agent.sh on the end-point"]
    TOK --> EP
    EP -->|no| E(["End"])
                ```

  - CyFORT-Wazuh (Wazuh manager, indexer and dashboard): `radar/build-radar.sh --core-only`, or with a RADAR scenario, brings up `radar/docker-compose.core.yml`. See: `docs/manual/radar_docs/radar-getting-started.md`.
  - C-CyFORT-Suricata (optional): see `docs/manual/custom_deployments/suricata/suricata_installation.md`.
  - Anomaly detection (optional): new deployments use SONAR (`sonar/sonar.sh`), and ADBox v1 is maintained for existing deployments only.

4. Configure components via respective software configuration management (SCM) mechanism, e.g., `radar/.env` (documented in `radar/env.example`), `radar/config.yaml`, or the RADAR GUI (`radar/radar.sh gui`).

### Rationale
To centralize and simplify IDPS components configuration management.
