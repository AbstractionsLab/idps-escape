Product presentation

IDPS-ESCAPE: AI-driven intrusion detection and automated security response

IDPS-ESCAPE turns detection into action. It combines signature-based engines (Wazuh, Suricata) with machine learning anomaly detection to catch both known and emerging threats, combines their evidence over time, then automatically fires risk-scaled responses, from alert emails to host isolation, enriched with live cyber threat intelligence. Incident cases are created automatically, closing the loop from detection to remediation. Built for SMEs, SOC teams, and CERT/CSIRT entities under the CyFORT project.

Core capabilities

From detection to response

RADAR — risk-aware automated response

RRCF-based behavioral and signature detection, now built around a manager-centric architecture with a programmatic wazuh_api module. Tiered active responses scale automatically to computed risk level.

RRCF wazuh_api Active response

SONAR — multivariate anomaly detection

Multivariate time-series anomaly detection on Wazuh alerts, with a choice of detector: Microsoft MVAD (MTAD-GAT), a fast PCA model or an EWMA baseline. Anomalies come back as Wazuh alerts, each delivered once, and sonar evaluate measures detection quality on labelled data. Runs as a standalone package.

MVAD · PCA · EWMA Wazuh alerts sonar evaluate

Hybrid detection with temporal fusion

Three layers of defense: Wazuh/Suricata signature rules catch known patterns, RADAR (RRCF) detects behavioral anomalies per user or host, and SONAR identifies multivariate anomalies. RADAR combines a signature alert with a recent anomaly on the same user or host, so together they can reach a response tier that neither reaches alone.

Wazuh Suricata Temporal fusion

CTI enrichment via DECIPHER

SATRAP-DL's DECIPHER subsystem queries MISP IOC feeds for blacklisted IPs, malicious domains, and hash indicators. The resulting CTI score T is fused into the normalized risk score R.

DECIPHER SATRAP-DL MISP

Flowintel case management

Incident cases are created automatically by DECIPHER in Flowintel when risk thresholds are crossed. Alert emails include the case URL, risk score breakdown, and full IOC context.

Flowintel Case creation Tiered alerts

Manager-centric enrichment & deployment

Enrichment logic (GeoIP, web) now lives in the Wazuh manager instead of per-endpoint helpers. Onboarding, group assignment, enrollment hardening, and scenario teardown are all driven by scripted manager entrypoints (radar.sh, bootstrap-agent.sh) — no Ansible required. Everything installed on endpoints ships as one radar-agent folder, with versioned active-response scripts.

Detection scenarios

Self-contained, deployed one by one

A RADAR scenario is a complete use case: decoders, rules, agent configuration, risk weights and responses, deployed and undone on its own from the command line or the GUI. A fleet-wide baseline rule set for PowerShell and command-shell execution is always active alongside them.

Suspicious login

Signature · per user

Failed-login bursts, impossible travel computed from manager-side GeoIP and ASN enrichment, credential compromise (failures followed by an impossible-travel success) and Microsoft 365 brute force. The response escalates from an email to firewall-drop, and to locking the named Linux user only when the alert is combined with off-hours evidence.

rules 210013–210031 firewall-drop lock_user_linux.sh

Off-hours activity

Rule mode and model mode · per user · new in v2.2.0

Working hours are declared per schedule group (time zone, workdays, overnight shifts) and every archived event is marked on or off hours as it is indexed. Staff with fixed hours are alerted once per off-hours burst, from the first event; administrators who sometimes work late are judged by a per-user model of their usual off-hours count. Both feed suspicious_login's anomaly side and fuse with its signature alerts.

radar-off-hours pipeline rules 210040–210041 Temporal fusion

GeoIP detection

Signature · per source

SSH logins and web requests from countries outside an approved whitelist, checked against a CDB list on the manager. With no CTI source for locations, the whole risk weight sits on the signature, so its main rules reach the blocking tier.

rules 100900–100903 whitelist_countries firewall-drop

Web scanning

Signature · per source IP

Scanner tool User-Agents, failed-request floods and HTTP method abuse. A scan is confirmed only when two of these indicators come from the same source IP within a short window, so an isolated 404 burst or scanner string is recorded but does not alert.

rules 100810–100840 Suricata eve.json firewall-drop (opt-in)

Log volume growth

Anomaly (RRCF) · per endpoint

Learns each endpoint's own baseline of /var/log size and flags unexplained growth, a sign of malware, brute force or runaway processes. At the top tier it can stop allowlisted services found in the alert's context.

rules 100300, 100309 OpenSearch AD terminate_service.sh

Linux resource utilization

Anomaly (RRCF) · per endpoint · new in v2.2.0

Samples CPU and memory on each Linux endpoint and flags sustained load that is abnormal for that endpoint, such as cryptomining, runaway processes or resource exhaustion, which fixed thresholds tuned for normal peaks miss.

rules 100320, 100321 resource collector terminate_service.sh

Signature and anomaly fusion

New in v2.2.0

A failed-login burst and off-hours activity by the same user are stronger evidence together than apart. RADAR combines them as they arrive: each alert looks back for the strongest alert of the other kind on the same user or host and uses it for the evidence it cannot carry itself. Nothing waits for a counterpart. A missing anomaly never lowers a score, and a counterpart never changes what is blocked or locked.

Full operational lifecycle in the browser

MAPE-K automated response cycle

Monitor to response, continuously
1. Monitor

Wazuh agents and Suricata sensors collect logs, network events, and endpoint telemetry, feeding the OpenSearch indexer in real time.

2. Analyze

SONAR (multivariate ML) and RADAR (RRCF behavioral) detect anomalies. Wazuh rules simultaneously match known signature attack patterns.

3. Plan

The RADAR risk engine fuses anomaly intensity A, signature risk S, and DECIPHER CTI score T into a weighted R = wₐ·A + wₛ·S + wₜ·T, assigning a Low, Medium, or High response tier. With fusion, a recent alert of the other kind on the same entity fills the missing term.

4. Execute

Active responses fire automatically: email alerts, Flowintel incident case creation, and strong actions (IP block, host isolation, credential disable) scaled to the risk tier.

5. Knowledge

DECIPHER queries MISP IOC feeds to keep threat intelligence current. Flowintel accumulates case history and SONAR models are retrained with fresh alert evidence.
