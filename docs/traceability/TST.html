1.1 Deploy ADBox via Docker and shell scripts TST-001

Preconditions and setup actions

  • Docker version 26.0.0
  • User with root privileges
  • 26 GB storage on the machine
  • git version 2.44.0

Test steps

  1. Clone the ADBox repository. git clone https://github.com/AbstractionsLab/idps-escape.git

  2. Change the working directory to the cloned folder containing all the files along with the Dockerfile.

cd siem-mtad-gat
  1. Build the image.

3a. Make the script executable: chmod +x build-adbox.sh

3b. And execute it as follows

./build-adbox.sh
  1. Run the container by executing the bash file containing the run commands.

4a. Make it executable: chmod +x adbox/adbox.sh

4b. And execute it as follows

./adbox/adbox.sh -h

Expected outcome

Step 1. A copy of siem-mtad-gat folder in local folder

Step 3. In the list of docker images (docker images), the following should be present

REPOSITORY                      TAG       IMAGE ID       CREATED         SIZE
siem-mtad-gat                   v0.1.4    ...   ...            ...

Step 4b. Display ADBox help message

usage: driver.py [-h] [-i] [-u USECASE] [-c] [-s]

IDPS-ESCAPE ADBox, an open-source anomaly detection toolbox, developed in project CyFORT.

options:
  -h, --help            show this help message and exit
  -i, --interactive     run the interactive console for training and prediction
  -u USECASE, --usecase USECASE
                        specify a configuration scenario/use-case file for training and prediction
  -c, --connection      check connection with Wazuh
  -s, --shipping        enable data shipping to Wazuh

1.3 Install ADBox as dev container TST-003

Preconditions and setup actions

  • Docker engine version 26.1.3
  • Docker desktop version 1.0.35
  • Visual Studio Code version 1.83.1 (system setup)
  • Dev Containers extension for VS Code by Microsoft version v0.315.1
  • at least 26 GB of persistent/disk storage

Test steps

  1. Clone this repository: git clone https://github.com/AbstractionsLab/idps-escape.git
  2. Start Docker Desktop if not already running.
  3. Open the project folder in VS Code.
  4. Select the "Reopen in Container" option in the notification that pops up in VS Code or run it via the command palette.
  5. Open a terminal in VS Code and run poetry install in the container to install all dependencies.
  6. Run ADBox using its entrypoint.
  poetry run adbox

Expected outcome

Step 1. Repository creation

Step 4. Container created and terminal open.

Step 5. Poetry install terminated with Installing the current project: siem-mtad-gat (0.1.4).

Step 6. Run ADBox default mode:

  IDPS-ESCAPE ADBox running in default mode

3.21 Validate detection of linux_resource_utilization TST-062

This test checks that RADAR raises an anomaly when CPU usage on a Linux agent goes far above its normal level. The detector is trained on baseline data that matches the agent's normal CPU and memory usage. A CPU load of 90% is then applied while memory stays at its normal level. The test passes if the detector reports an anomaly during the CPU load and the anomaly is caused only by CPU.

The detector LINUX_RESOURCE_UTILIZATION_DETECTOR checks each agent every minute, using four values: cpu_usage_avg, cpu_usage_max, memory_usage_avg and memory_usage_max. It raises an alert when anomaly_grade ≥ 0.01 and confidence ≥ 0.01.

Deployment and onboarding are validated by TST-061. This test repeats those steps in every run only to start from a clean state; the outcomes are not validated again.

Preconditions and setup actions

  • Same preconditions as TST-061.
  • Successful execution of TST-061 with the same controller and agent host to be used in this test.
  • stress-ng at least v0.19.02 is installed on the agent host (sudo apt-get install -y stress-ng).
  • For the optional step, Flowintel is correctly configured and reachable from the controller host.

Setup

The following steps are executed only once, before the first run of this test.

  1. From the root of the project, copy the simulation script and the radar-agent folder (which holds bootstrap-agent.sh and uninstall-agent.sh) to the agent's host, and make the simulation script executable:
scp radar/radar-test-framework/simulate/scenarios/linux_resource_utilization.sh <user>@<agent-host>:~/
scp -r radar/radar-agent <user>@<agent-host>:~/
ssh <user>@<agent-host>
chmod +x linux_resource_utilization.sh
  1. Run the following on the agent host while it is idle. It uses the same calculation as the RADAR collector radar-linux-resource-utilization-metric.sh, takes 5 samples 60 seconds apart, and prints their average:
for i in $(seq 1 5); do
  read -r t1 i1 < <(awk '/^cpu / {t=0; for(k=2;k<=NF;k++) t+=$k; print t, $5}' /proc/stat); sleep 1
  read -r t2 i2 < <(awk '/^cpu / {t=0; for(k=2;k<=NF;k++) t+=$k; print t, $5}' /proc/stat)
  awk -v dt=$((t2-t1)) -v di=$((i2-i1)) \
    '/^MemTotal:/{t=$2} /^MemAvailable:/{a=$2}
    END{printf "cpu=%.2f mem=%.2f\n", (1-di/dt)*100, (1-a/t)*100}' /proc/meminfo
  [ "$i" -lt 5 ] && sleep 59
done | tee /dev/stderr | awk -F'[= ]' '{c+=$2; m+=$4; n++} END{printf "average: cpu=%.2f mem=%.2f\n", c/n, m/n}'

  1. On the controller host, set baseline_cpu_pct and baseline_mem_pct in the ingest part of the linux_resource_utilization section of radar/config.yaml to the printed averages. The other ingest values stay as they are.

  2. On the controller host, prepare .env and start the GUI of RADAR as in steps 1-2 of TST-061.

Assumptions

  1. The baseline values in config.yaml have been set according to the agent's host normal usage metrics, as described in the Setup section.
  2. Nothing runs on the agent's host other than the operating system, the Wazuh agent and the stress script.
  3. Installing the agent causes a short CPU spike, which the detector may report as an anomaly.
  4. Each run starts from a clean state, using the steps in Cleanup.

Acceptance criteria

The test is run 10 times. It passes if, in every run:

  1. An anomaly with cpu_usage_max ≥ 80% is reported.
  2. That anomaly has anomaly_grade ≥ 0.8 and confidence ≥ 0.3.

In addition, the expected outcome of step 5 holds in the first run.
