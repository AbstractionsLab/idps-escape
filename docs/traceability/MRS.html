1.0 SONAR Mission Requirements

Mission-level requirements for SONAR (SIEM-Oriented Neural Anomaly Recognition) subsystem - the production multivariate anomaly detection system.

1.1 Multivariate Anomaly Detection MRS-004

The IDPS-ESCAPE system architecture SHALL include a multivariate anomaly detection (AD) subsystem to detect anomalies across at least two features/dimensions in at least one of the following types of security event capturing data sets: host-based and network-based.

Implementation: This requirement is fulfilled by: - SONAR (primary/production): SIEM-Oriented Neural Anomaly Recognition using Microsoft MVAD library (see MRS-042) - ADBox v1 (maintenance): Legacy MTAD-GAT implementation maintained for backward compatibility

Rationale

To detect deviations from an a priori normal baseline system behavior, possibly caused by malicious actors. SONAR provides modern anomaly detection capabilities with better Wazuh integration, while ADBox v1 remains available for existing deployments.

Successful validation according to the corresponding test case specification

1.1 SONAR Production Anomaly Detection System MRS-042

The IDPS-ESCAPE system architecture SHALL include SONAR (SIEM-Oriented Neural Anomaly Recognition) as the primary production multivariate anomaly detection subsystem, superseding ADBox v1 (MTAD-GAT) which remains in maintenance mode for backward compatibility.

Rationale

SONAR provides improved detection capabilities through Microsoft's MVAD (Multivariate Anomaly Detection) library, offers better integration with Wazuh through native data streams, includes debug mode for offline development, and provides a more maintainable architecture using dataclasses and typed Python. ADBox v1 remains available for existing deployments and specific use cases requiring MTAD-GAT algorithms, but new deployments should use SONAR.

Key differences

Aspect SONAR (Production) ADBox v1 (Maintenance)
Algorithm Microsoft MVAD (SR-CNN, Spectral Residual) MTAD-GAT (PyTorch)
Status Active development Maintenance only
Integration Native Wazuh data streams OpenSearch direct
Configuration YAML scenarios Use-case YAML
Testing Debug mode with synthetic data Requires live Wazuh
CLI poetry run sonar ./adbox.sh

Related requirements

  • MRS-004: Multivariate Anomaly Detection (parent requirement)
  • MRS-030: Deep Learning Technique (implemented by SONAR)
  • MRS-032: Host and Network Ingestion (SONAR ingests from Wazuh)
  • MRS-039: Offline AD (SONAR debug mode)
  • MRS-041: Standalone AD Subsystem (SONAR runs independently)

Acceptance criteria

Successful validation according to the corresponding test case specification, including: - SONAR can train models using historical Wazuh alerts - SONAR can detect anomalies in real-time, batch, or historical modes - SONAR properly ships anomaly results to Wazuh data streams - SONAR debug mode enables offline testing without Wazuh - Documentation clearly distinguishes SONAR from ADBox v1

importance 5
urgency 5

2.2 Intrusion Prevention MRS-007

The IDPS-ESCAPE system architecture SHALL include intrusion prevention (IP) capabilities through automated response mechanisms.

Implementation: This requirement is fulfilled by the RADAR (Real-time Alert Detection and Response) subsystem, which provides: - Risk-based automated response to detected threats - Active response playbooks for containment (firewall rules, user lockout, host isolation) - Integration with anomaly detection systems for coordinated defense - Auditable action logging and compliance tracking

Rationale

To enable rapid, automated reactive corrective measures that mitigate intrusions before significant damage occurs. Manual-only response is insufficient for modern threat landscapes requiring sub-second response times.
